# 01 数据资产（菜单组实施规划）

> 规格来源：[`../nqboard-migration-plan.md`](../nqboard-migration-plan.md)（主文档）§3.1/3.2（DDL）、§D1~D3（取数决策）、§4.1~4.5（取数与入库）、§12（验收）。菜单归属：主文档 §1.4 数据资产组（6410~6450）。
> 定位：整个 sniper 的**地基模块**——为 02 扫描信号、03 信号台账提供全部行情/事件数据。自身零 LLM、零业务决策。对应主文档分期 **M1**（DDL + Provider + 网关 + 回填 + 日更）。

## 1. 数据库设计

> 13 张行情/事件表与业务表**统一 BaseEntity 范式**（主文档 §3 头注）：`id` 雪花主键 + 审计五列 create_by/create_time/update_by/update_time/del_flag；原复合自然键转 UNIQUE KEY，`INSERT ... ON DUPLICATE KEY UPDATE` 命中 UK，幂等语义不变；不走 BaseMapper 单条 CRUD，批量路径中审计列由代码显式赋值（create_by='sniper'、create_time=now()、del_flag='0'，命中 UK 时 update_time=now()），不依赖填充器；del_flag 恒 '0' 不参与业务过滤，保留 `fetched_at`。脚本落 `db/nqboard_sniper.sql`，房规对照主文档 §3 头注（反引号 / InnoDB / utf8mb4_general_ci / ROW_FORMAT=Dynamic）。

## 2. 数据获取

### 2.1 对外契约：DataGateway（唯一 IO 边界，主文档 §4.1）

本模块**实现**该接口（`data/` 包），02 扫描信号、03 信号台账**消费**它。纪律：每个方法显式收 `asOf`，窗口计算一律锚定 asOf 回溯（唯一例外 Stage0 次新过滤以快照日为锚）。

```java
public interface DataGateway {
    // 行情
    List<Price> getPrices(String ticker, LocalDate start, LocalDate end, Adjust adjust); // 默认 QFQ
    List<Price> getIndexPrices(String indexCode, LocalDate start, LocalDate end);
    MarketSnapshotFrame getSpotSnapshot(LocalDate asOf);          // 全市场快照(sniper_market_snapshot)
    // 基础
    List<LocalDate> getTradingDays(LocalDate start, LocalDate end);
    LocalDate resolveAsOf(LocalDate raw);                          // 非交易日前移
    Set<String> getIndexConstituents(String indexCode);            // 最新快照日
    StockBasic getStockBasic(String code);                         // 含 list_date/industry
```

### 2.2 Provider 路由与降级链（主文档 §4.2）


QoS 参数（对齐 Python 版）：

| 机制 | 参数 | 实现建议 |
|---|---|---|
| Tushare 节流 | 350ms 全局间隔 | 自研令牌桶/计数器，全局锁间隔照 Python `_throttle` |
| Tushare 重试 | 3 次，限频错误退避 2n s、其他 1n s + rand | 自实现双判定（照 `_call`），不引 Spring Retry |
| 东财节流 | 500ms 下限 | 同上 |
| 东财熔断 | 7 类连接错误 → OPEN 300s | Sentinel 熔断规则（或自研状态机），OPEN 期间直接路由腾讯/新浪 |
| 重试（东财/腾讯/新浪） | 最多 5 次，退避 2n+rand(0,1) s | 照 Python `run_throttled_retry` |
| 日预算 | 300 次/日，仅"东财主源"模式计数；Tushare 主源不消耗 | `AtomicInteger` + `sniper_daily_run.budget_used` 持久化；耗尽 → Stage1 跳票记 `stage1_skipped_due_to_budget` |
| 请求审计 | 全部 HTTP 出站 | AOP 切面统一写 `sniper_request_log`（属 05 模块的表，本模块负责写入） |

**映射②（兜底 THS）**：`公告日期`→`ann_date`、`变动股东`→`holder_name`、`变动数量`→`change_vol`（文本"万股"解析成股）、`交易均价`→`avg_price`、`剩余股份总数`→`after_shares`、`变动途径`→`holder_type`。

### 3.10 主力资金流 `sniper_fund_flow_daily`

- 主源：`moneyflow` params `{"ts_code":..,"start_date":"<asOf−30d>","end_date":"<asOf>"}`。兜底：东财个股资金流（单位已是元）。
- **main_net 必须为元**——阈值 `max(均值×0.8, 1.0元)` 与 reasoning 的 `net_3d/1e8 亿` 格式化都按元硬编码。

**映射①（Tushare `moneyflow`，金额单位均为万元）**：

| 接口字段 | 表列 | 换算 |
|---|---|---|
| `ts_code` | `code` | "."前6位 |
| `trade_date` | `trade_date` | YYYYMMDD→DATE |
| `net_mf_amount` | `main_net` | **×1e4→元** |
| `buy_elg_amount − sell_elg_amount` | `super_net` | ×1e4→元 |
| `buy_lg_amount − sell_lg_amount` | `large_net` | ×1e4→元 |
| `buy_md_amount − sell_md_amount` | `medium_net` | ×1e4→元 |
| `buy_sm_amount − sell_sm_amount` | `small_net` | ×1e4→元 |
| 各 `*_vol` 列 | —（不入库） | 未消费 |

**映射②（兜底 EM `stock_individual_fund_flow`）**：`日期`→`trade_date`、`主力净流入-净额`→`main_net`、`超大单净流入-净额`→`super_net`、大/中/小单同法；各"净占比"列不入库。

### 3.11 龙虎榜 `sniper_dragon_tiger`

- 主源：`top_list` params `{"trade_date":"<当日YYYYMMDD>"}` **全市场一次**（放日更任务 15:15，比逐票区间省 ~30 倍）。兜底：东财 LHB 明细区间（datacenter-web 接口）。
- 消费：dragon_tiger agent 查近 30 日记录（5 日上榜次数、5 日净买合计、原因关键词分）。

**映射①（Tushare `top_list`，金额单位为元）**：`ts_code`→`code`、`trade_date`→DATE、`reason`→`reason`、`net_amount`→`net_buy`（**元原样**）、`l_buy`→`buy_amt`、`l_sell`→`sell_amt`、`pct_change`→`change_pct`；name/close/turnover_rate/amount/l_amount/net_rate/amount_rate/float_values 不入库。

**映射②（兜底 EM `stock_lhb_detail_em`）**：`代码`→`code`、`上榜日`→`trade_date`、`上榜原因`→`reason`、`龙虎榜净买额`→`net_buy`、`龙虎榜买入额`→`buy_amt`、`龙虎榜卖出额`→`sell_amt`、`涨跌幅`→`change_pct`。

### 3.12 限售解禁 `sniper_restricted_release`

- 主源：`share_float` params `{"ts_code":..,"start_date":"<asOf−3y>","end_date":"<asOf+2y>"}`。兜底：东财解禁队列。
- 查询失败 **fail-open**（不拦截信号，`gate.py` 语义）。

**映射①（Tushare `share_float`）**：

| 接口字段 | 表列 | 说明 |
|---|---|---|
| `ts_code` | `code` | "."前6位 |
| `float_date` | `plan_date` | YYYYMMDD→DATE |
| `float_share` | `shares` | **股，原样** |
| `float_ratio` | `float_ratio` **和** `float_mv_ratio` | **百分点→小数 ÷100**（8.0→0.08）；两列同值：tushare 口径实为占总股本（更小、更保守，只会放过边缘 case 不会误杀），靠 source 区分 |
| `holder_name`/`share_type`/`ann_date` | —（不入库） | gate 只消费 date+ratio |

**映射②（兜底 EM `stock_restricted_release_queue_em`）**：`解禁时间`→`plan_date`、`解禁数量`→`shares`（股）、`实际解禁市值`→`market_value`（元）、`占解禁前流通市值比例`→`float_mv_ratio`（**真流通市值口径**，百分数→÷100）、`float_ratio` 留空。

## 4. 入库规则

### 4.1 通用规则（主文档 §4.3.0，6 条）

1. **入库单位分层**：行情/快照表原样存 + source 标注（量比等比值特征对单位不敏感，bit-exact 优先）；事件/资金类表入库即换算成对外单位（元、股、小数比例）——消费侧阈值硬编码依赖这些单位。
2. **upsert 幂等**：全部 `INSERT ... ON DUPLICATE KEY UPDATE`，PK/UK 即防重，重复跑不产生重复行。
3. **日期格式**：DATE 列一律 `YYYY-MM-DD`；`YYYYMMDD` 先转换再入库。
4. **失败语义**：主源失败→按兜底链降级→全链失败记 `sniper_daily_run.detail` 缺数标记；消费侧按各 agent "缺失→neutral 40 / fail-open" 语义兜底，**不允许因单表缺数抛异常终止扫描**（行情除外：无行情=Stage1 淘汰，这本身就是行为）。
5. **请求审计**：所有出站 HTTP（含兜底链）写 `sniper_request_log`（05 模块的表）。
6. **Tushare 信封与翻页**：见 §2.3 尾注。

### 4.2 复权与 qfq 合成（主文档 D3 + §4.3.4）

- 只存 `none` 和 `qfq` 两套 + 复权因子表；**hfq 零消费不建行**。
- qfq 合成：`qfq_price = none_price × factor ÷ max_factor`（max_factor=该票**全历史** max(factor)，OHLC 四列同乘；volume/amount/pre_close 不乘——复权只作用价格）。
- **除权检测**：当日 factor ≠ 该票前一交易日 factor → 该票全历史 qfq 重拉重算覆盖（每天几十~200 只，可控）；`none` 行 insert-only 永不重拉。
- **涨跌停价是唯一"必须不复权"路径**：停牌检查显式 adjust="none"；正式涨跌停价计算用**交易所发布的前收盘价**（除权除息日用调整后 reference_close）。Stage1/Stage3 的 `limit_up_distance_pct` 等特征在 qfq 序列上按板块比例近似计算，只用于打分——两套并存是现状语义，照搬。

### 4.3 每日数据更新任务（收盘后，扫描之前；主文档 §4.4）

| 时间(约) | 任务 | 逻辑 |
|---|---|---|
| 15:05 | 快照 | 东财 clist 全市场（失败走 §2.2 快照兜底链）→ `sniper_market_snapshot` 当日 upsert |
| 15:08 | 交易日历 | `trade_cal` 增量 → `sniper_trade_calendar` |
| 15:10 | 日行情增量 | Tushare `daily(trade_date=当日)` 全市场 → none 行；同口径 `adj_factor` → 因子表 |
| 15:12 | qfq 增量+重算 | ① 当日 qfq 本地算并 upsert；② 除权检测 → 变化票逐票重拉全历史覆盖 |
| 15:15 | 事件数据 | 龙虎榜 `top_list` 全市场 1 调；其余（新闻/增减持/资金流/解禁/板块K/财务）按需增量——"拉取即入库"，表幂等保证重跑无副作用 |
| 15:35 | 扫描 | （02 模块 ScanPipeline，不属于本模块） |

### 4.4 历史回填（一次性，主文档 §4.5）

1. `stock_basic` 全量、`trade_cal` 全量；
2. 循环交易日逐日 `daily(trade_date)` + `adj_factor(trade_date)`（全市场各 1 调，~250 调/年）；
3. qfq 历史用因子本地合成，**抽样 ≥50 只与 Python `get_prices(adjust='qfq')` 逐字段比对 bit-exact**（判定口径见主文档 §12 头注：按存储精度取整后相等），完全一致才允许此模式；不一致的票退回逐票拉取；
4. 指数行情/成分随用随补；快照历史无法回填（已知失真，对拍选近期日期）。

## 6. 页面定义

### 6.2 市场快照（6420）

- Tab 股东增减持：code+公告日区间；列 ann_date、holder_name、holder_type、change_vol（减持负值标红）、avg_price、after_shares、source。

- 交易日历：按年筛选；列 cal_date、is_open。

## 7. 对拍与验收（主文档 §12 数据相关行）

| 层级 | 方法 | 通过标准 |
|---|---|---|
| 数据级 | 录制 Python `CN_REQUEST_LOG` 3 个真实交易日 → Java provider fixtures 回放（WireMock） | 同输入 → 相同 endpoint 序列与 n_rows |
| 回填验证 | 抽样 ≥50 只与 Python `get_prices(adjust='qfq')` 逐字段比对 | bit-exact（按存储精度取整后相等，主文档 §12 头注统一口径）；不一致票退回逐票拉取 |
| 运行验证 | 日更任务连续运行 + 影子运行 | 同一天结束后库内数据与 Python 版一致（对拍以"日终一致"为准） |

对拍期间直接用本模块的日行情/快照/请求审计页面直观看数据质量——这正是菜单规划把数据资产排在 M1 先行的原因。

## 8. 模块边界

- **下游**：02 扫描信号（行情/快照/成分/事件/财务/板块，DataGateway 全量消费）；03 信号台账（日行情 none/qfq、沪深300 指数行情）。
- **上游**：外部 Tushare/东财/腾讯/新浪 HTTP；Quartz 日更 Job（触发与幂等键属 05 模块的调度衔接，本模块提供可手动触发的同一 Service）。
- **明确不做**：hfq 行（零消费，主文档 D3）、北向分析师数据（仅预检告警例外）、`src/backtesting/` + `src/backtester.py` 回测/ML 管线、`--intraday` 盘中。
- **不做业务决策**：本模块无阈值判断、无 LLM，缺数语义由消费方定义（§4.1 第 4 条）。
