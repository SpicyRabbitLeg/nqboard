# 05 运维监控（菜单组实施规划）

> 规格来源：[`../nqboard-migration-plan.md`](../nqboard-migration-plan.md)（主文档）§3.4（审计表）、§3.5（写入方对照）、§4.2（日预算）、§10（调度与运行时）。菜单归属：主文档 §1.4 运维监控组（6510/6520/6530）。
> 定位：**跨期贯穿的只读观测层**——三张审计表由各模块运行时写入，本模块只做查询展示与调度衔接说明。建设跨 M1/M5/M6 三期（见 §8）。

## 0. 模块范围与菜单

| 菜单(ID) | 页面 | 操作按钮 |
|---|---|---|
| 任务运行记录(6510) | `sniper_daily_run` 查询 | —（只读） |
| LLM调用审计(6520) | `sniper_llm_call_log` 查询 | —（只读） |
| 外部请求审计(6530) | `sniper_request_log` 查询 | —（只读） |

依赖字典：`sniper_run_phase`（data_update/scan/track/review）、`sniper_run_status`（running/done/failed）、`sniper_llm_workflow`、`sniper_llm_status`。

## 1. 数据库设计

```sql
-- 调度幂等与预算记账（Quartz Job 幂等键；实体继承 BaseEntity）
CREATE TABLE `sniper_daily_run` (
  `id`          bigint NOT NULL COMMENT '雪花id(ASSIGN_ID)',
  `create_by`  varchar(255) NULL DEFAULT NULL COMMENT '创建人',
  `create_time` datetime NULL DEFAULT NULL COMMENT '创建时间',
  `update_by`  varchar(255) NULL DEFAULT NULL COMMENT '修改人',
  `update_time` datetime NULL DEFAULT NULL COMMENT '修改时间',
  `del_flag`   char(1) NULL DEFAULT '0' COMMENT '删除状态（0未删除、1删除）',
  `run_date`    date NOT NULL,
  `phase`       varchar(20) NOT NULL COMMENT 'scan/track/review/data_update',
  `status`      enum('running','done','failed') NOT NULL,
  `budget_used` int NOT NULL DEFAULT 0 COMMENT '东财主源日预算消耗',
  `detail`      json NULL COMMENT '缺数标记/统计',
  `started_at`  datetime NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `finished_at` datetime NULL,
  PRIMARY KEY (`id`) USING BTREE,
  UNIQUE KEY `uk_run` (`run_date`, `phase`)
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT='每日运行记账' ROW_FORMAT = Dynamic;

-- LLM 调用审计（P-07 缺口：token/成本可离线评估；实体继承 BaseEntity）
CREATE TABLE `sniper_llm_call_log` (
  `id`           bigint NOT NULL COMMENT '雪花id(ASSIGN_ID)',
  `create_by`  varchar(255) NULL DEFAULT NULL COMMENT '创建人',
  `create_time` datetime NULL DEFAULT NULL COMMENT '创建时间',
  `update_by`  varchar(255) NULL DEFAULT NULL COMMENT '修改人',
  `update_time` datetime NULL DEFAULT NULL COMMENT '修改时间',
  `del_flag`   char(1) NULL DEFAULT '0' COMMENT '删除状态（0未删除、1删除）',
  `called_at`    datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `workflow`     varchar(40) NOT NULL COMMENT 'news_sentiment/policy_sentiment/flat_decision',
  `tickers`      json NULL,
  `input_digest` varchar(64) NULL,
  `output_json`  json NULL,
  `status`       enum('ok','parse_error','timeout','http_error') NOT NULL,
  `latency_ms`   int NULL,
  `error`        varchar(500) NULL,
  PRIMARY KEY (`id`) USING BTREE,
  KEY `idx_llm_time` (`called_at`) USING BTREE
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT='LLM调用审计' ROW_FORMAT = Dynamic;

-- 外部请求审计（Python CN_REQUEST_LOG 等价物，对拍 fixtures 录制源；append-only，审计列由 AOP 写入路径显式赋值）
CREATE TABLE `sniper_request_log` (
  `id`          bigint NOT NULL COMMENT '雪花id(ASSIGN_ID)',
  `create_by`   varchar(255) NULL DEFAULT NULL COMMENT '创建人',
  `create_time` datetime NULL DEFAULT NULL COMMENT '创建时间',
  `update_by`   varchar(255) NULL DEFAULT NULL COMMENT '修改人',
  `update_time` datetime NULL DEFAULT NULL COMMENT '修改时间',
  `del_flag`    char(1) NULL DEFAULT '0' COMMENT '删除状态（0未删除、1删除）',
  `called_at`  datetime(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  `endpoint`   varchar(60) NOT NULL,
  `source`     varchar(20) NOT NULL,
  `params`     json NULL,
  `status`     varchar(10) NOT NULL,
  `n_rows`     int NULL,
  `elapsed_ms` int NULL,
  `error`      varchar(500) NULL,
  PRIMARY KEY (`id`) USING BTREE,
  KEY `idx_req_time` (`called_at`) USING BTREE
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT='外部请求审计' ROW_FORMAT = Dynamic;
```

> 三张表统一 BaseEntity 范式（id + 审计五列，主文档 §3 头注）：`sniper_daily_run` / `sniper_llm_call_log` 走标准 CRUD、审计列由填充器写；`sniper_request_log` 是 append-only 高频表，审计列由 AOP 写入路径显式赋值（不依赖填充器），del_flag 恒 '0' 不参与过滤。三张表 DDL 随 M1 一次性建齐。

## 2. 数据获取（写入方在别的模块，本模块只读）

| 表 | 写入方 | 触发时机 | 写入内容 |
|---|---|---|---|
| `sniper_daily_run` | Quartz Job 包装器（4 个 Job 首尾各写一次） | data_update 15:05~15:15 / scan 15:35 / track 15:40 / review 周五 16:00 | run_date/phase/status/budget_used/detail；**UK(run_date,phase) 即幂等键** |
| `sniper_llm_call_log` | `DifyClient`（每次调用收尾） | 每次扫描的 LLM 调用（≤17 次/扫描） | workflow/tickers/input_digest/output_json/**成功失败都写** |
| `sniper_request_log` | HTTP 拦截器（AOP 切面统一写） | 全部出站请求（含兜底链） | endpoint/source/params/n_rows/elapsed_ms/error；Java 侧默认全量（Python CN_REQUEST_LOG 是 opt-in JSONL） |

本模块的"数据获取"= 纯库内查询，无外部端点。

## 3. 接口数据与数据库字段映射

无转换——页面字段与表列一一对应（分页 + 时间范围过滤）。`detail` / `params` / `output_json` / `tickers` 四个 JSON 列由前端格式化展示。

## 4. 入库/写入规则（对本模块而言是"谁写、何时写"的契约）

- `sniper_daily_run`：Job 开始写 `running`、结束改 `done`/`failed`（同 UK 行更新）；**重复触发同 (run_date, phase) 由 UK 兜底**，包装器需按 UK 查已有行再决定写 running 或跳过。
- `sniper_llm_call_log`：失败（timeout/http_error/parse_error）也必须落行——这是 fail-closed 行为可审计的前提。
- `sniper_request_log`：append-only，AOP 切面写，异常时 error 字段落异常摘要（≤500 字），不因审计失败阻断主链路（写失败仅日志告警）。

## 5. 后端接口

落位：`controller/OpsController` + `service/OpsService`（查询逻辑在 Service 层，Controller 只做参数组装——平台规范不允许 Controller 直连 Mapper/库；三张表的实体 Service/Mapper 按平台标准分层建立）。

> 下表路径为**前端/网关路径**（`/sniper/**`）；Controller 的 `@RequestMapping` 不带 `/sniper` 前缀（平台网关全局 StripPrefix=1，对齐 device `/category` 写法），路由在 Nacos `nqboard-gateway-dev.yml` 增加（README 全局约定）。分页按平台**延迟关联**范式，类上 `@Tag`/`@SecurityRequirement`、方法上 `@Operation`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sniper/ops/daily-run` | 分页；run_date 起止、phase、status |
| GET | `/sniper/ops/llm-log` | 分页；called_at 起止、workflow、status |
| GET | `/sniper/ops/request-log` | 分页；called_at 起止、endpoint、source、status |

## 6. 页面定义

### 6.1 任务运行记录（6510）
- 筛选：run_date 区间（默认近 7 天）、phase（4 态字典）、status。
- 列：run_date、phase、status（running 蓝/done 绿/failed 红）、budget_used（含 /300 进度条，仅 data_update/scan 有意义）、started_at、finished_at、耗时（前端计算）。
- 行展开：detail JSON（缺数标记、漏斗统计等）。

### 6.2 LLM调用审计（6520）
- 筛选：时间区间（默认当日）、workflow（3 态）、status（4 态）。
- 列：called_at、workflow、tickers（标签组）、status、latency_ms、error。
- 行展开：input_digest、output_json 折叠树。

### 6.3 外部请求审计（6530）
- 筛选：时间区间（默认近 1 小时，量大）、endpoint、source（tushare/em/tencent/sina/dify）、status。
- 列：called_at、endpoint、source、status、n_rows、elapsed_ms、error。
- 顶部快捷统计条：当日总请求数、东财源请求数（对照 300 预算）、失败率。

## 7. 调度衔接（Quartz 管理台配置清单，主文档 §10）

4 个 Job 挂 nqboard-visual-quartz 定时任务管理台（业务代码只提供 Job 类，cron 在管理台配）：

| 触发 | 任务 | 幂等保障 |
|---|---|---|
| 交易日 15:05~15:15 | 01 模块数据更新序列 | `sniper_daily_run(run_date,'data_update')` |
| 交易日 15:35 | 02 模块 ScanPipeline（现状 15:30 后手动跑，耗时 10-15 分钟） | UK(run_date,'scan') + report unique(as_of,universe) 重跑覆盖 |
| 交易日 15:40 | 03 模块 LedgerService ingest+fill+marks+close | position unique(cohort,ticker) + mark 全量重建 |
| 每周五 16:00 | 04 模块 ReviewService + 红线告警 | — |

注意：交易日判断以 `sniper_trade_calendar` 为准（01 模块），非交易日 Job 直接空跑退出（落一条 done + detail 标记）。

## 8. 对拍与验收 / 建设顺序

| 期 | 内容 | 验收 |
|---|---|---|
| M1 | 三张表 DDL 建齐 + AOP 请求审计写入 + 外部请求审计页（6530） | 对拍期间 request_log 全量可查（fixtures 录制源） |
| M5 | DifyClient 写 llm_call_log + LLM调用审计页（6520） | 成功/失败均落行；三态（ok/parse_error/timeout/http_error）可见 |
| M6 | Job 包装器写 daily_run + 任务运行记录页（6510） | 幂等键生效（重复触发不产生第二行）；预算消耗可见 |

## 9. 模块边界

- **上游**：三张表的写入方分别是 01（AOP/Job）、02（DifyClient/ScanPipeline）、03（track Job）、04（review Job）——本模块**零写入、零业务逻辑**。
- **不做**：告警推送（红线告警归 04，预算耗尽行为在 01 的 QoS 内实现）；本模块只负责"看得见"。
