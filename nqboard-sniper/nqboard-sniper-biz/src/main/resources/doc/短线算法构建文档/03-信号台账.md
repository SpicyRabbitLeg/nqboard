# 03 信号台账（菜单组实施规划）

> 规格来源：[`../nqboard-migration-plan.md`](../nqboard-migration-plan.md)（主文档）§3.3/3.5（台账表）、§7.4（费用/整手）、§9.1~9.4（台账规则）、§10（track Job）、§12（验收）。菜单归属：主文档 §1.4 信号台账组（6210/6211）。
> 定位：信号的**模拟成交与持仓跟踪**——把每日 entry_ok 信号入账、T+1 模拟成交、每日记 mark、止损/到期平仓。对应主文档分期 **M6**（依赖 02 已产出报告）。

## 0. 模块范围与菜单

| 菜单(ID) | 页面 | 操作按钮 |
|---|---|---|
| 仓位台账(6210) | 仓位列表 + 详情（隐藏路由 6211，每日 mark 收益曲线） | 手动跟踪 `sniper_ledger_track`(6212)；导出 `sniper_ledger_export`(6213) |

依赖字典：`sniper_position_status`（pending_entry/open/closed）、`sniper_close_reason`（stop_loss/horizon/gap_abort/never_filled）。

## 1. 数据库设计

```sql
-- 模拟台账仓位（tracking.py TrackedPosition 等价物；UK 幂等）
CREATE TABLE `sniper_ledger_position` (
  `id`               bigint NOT NULL COMMENT '雪花id(ASSIGN_ID)',
  `create_by`  varchar(255) NULL DEFAULT NULL COMMENT '创建人',
  `create_time` datetime NULL DEFAULT NULL COMMENT '创建时间',
  `update_by`  varchar(255) NULL DEFAULT NULL COMMENT '修改人',
  `update_time` datetime NULL DEFAULT NULL COMMENT '修改时间',
  `del_flag`   char(1) NULL DEFAULT '0' COMMENT '删除状态（0未删除、1删除）',
  `cohort_date`      date NOT NULL COMMENT '信号日, cohort_id=scan_<date>',
  `source_report`    varchar(200) NULL COMMENT '来源报告标识(ingested_reports 幂等审计)',
  `ticker`           varchar(9) NOT NULL,
  `status`           enum('pending_entry','open','closed') NOT NULL COMMENT 'gap_abort/never_filled是closed+close_reason,不占status',
  `entry_date`       date NULL,
  `entry_price`      decimal(16,4) NULL,
  `entry_cost`       decimal(16,2) NULL COMMENT '含费用,元',
  `signal_day_close` decimal(16,4) NULL COMMENT '信号日收盘(gap判定基准)',
  `quantity`         int NULL,
  `trial_cash_used`  decimal(16,2) NULL,
  `stop_price`       decimal(16,4) NULL COMMENT '=entry_price×(1-stop_pct)',
  `stop_from_date`   date NULL COMMENT '止损启用日(防对已存活仓位回溯止损)',
  `close_date`       date NULL,
  `close_price`      decimal(16,4) NULL,
  `close_reason`     enum('stop_loss','horizon','gap_abort','never_filled') NULL,
  `exit_proceeds`    decimal(16,2) NULL COMMENT '卖出净额(扣费)',
  `pnl`              decimal(16,2) NULL COMMENT '绝对盈亏,元',
  `pnl_pct`          decimal(10,6) NULL,
  `bench_ret_full`   decimal(10,6) NULL COMMENT '入场~平仓区间沪深300收益',
  `excess_ret`       decimal(10,6) NULL,
  `max_gain`         decimal(10,6) NULL,
  `max_drawdown`     decimal(10,6) NULL,
  `confidence`       decimal(5,2) NULL,
  `weighted_score`   decimal(10,6) NULL,
  `screen_score`     decimal(10,4) NULL,
  `reasons`          json NULL,
  `risk_flags`       json NULL,
  `analyst_summary`  json NULL,
  `market_ret_5d`    decimal(10,6) NULL COMMENT '信号日市场环境原始值;market_up/down由复盘按>=0派生',
  PRIMARY KEY (`id`) USING BTREE,
  UNIQUE KEY `uk_pos` (`cohort_date`, `ticker`),
  KEY `idx_pos_status` (`status`) USING BTREE
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT='模拟台账仓位' ROW_FORMAT = Dynamic;

-- 台账每日 mark（update_marks 每日一行；全量重建幂等）
CREATE TABLE `sniper_ledger_mark` (
  `id`             bigint NOT NULL COMMENT '雪花id(ASSIGN_ID)',
  `create_by`  varchar(255) NULL DEFAULT NULL COMMENT '创建人',
  `create_time` datetime NULL DEFAULT NULL COMMENT '创建时间',
  `update_by`  varchar(255) NULL DEFAULT NULL COMMENT '修改人',
  `update_time` datetime NULL DEFAULT NULL COMMENT '修改时间',
  `del_flag`   char(1) NULL DEFAULT '0' COMMENT '删除状态（0未删除、1删除）',
  `position_id`    bigint NOT NULL COMMENT '仓位id',
  `trade_date`     date NOT NULL,
  `close`          decimal(16,4) NOT NULL,
  `ret_from_entry` decimal(10,6) NULL,
  `ret_from_t0`    decimal(10,6) NULL COMMENT '相对信号日收盘',
  `bench_close`    decimal(16,4) NULL COMMENT '沪深300收盘',
  `bench_ret`      decimal(10,6) NULL,
  `excess_ret`     decimal(10,6) NULL,
  PRIMARY KEY (`id`) USING BTREE,
  UNIQUE KEY `uk_mark` (`position_id`, `trade_date`)
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT='台账每日mark' ROW_FORMAT = Dynamic;
```

写入方（主文档 §3.5）：`LedgerService.ingest/fill/updateMarks/close`——ingest 从报告 entry_ok 拷贝 confidence/weighted_score/quantity/reasons 等；fill 写 entry_*（T+1 开盘价+费用）；close 写 close_*；marks 全量重建。

## 2. 数据获取与依赖（来自上游模块）

| 步骤 | 依赖 | 说明 |
|---|---|---|
| ingest | 02 报告的 entry_ok 信号（`sniper_scan_signal`） | 幂等：`unique(cohort_date,ticker)` 冲突即跳过；**已有活跃（pending/open）仓位的票不重复入场**（active_tickers 检查） |
| fill | T+1 开盘价（日行情 none 行，经 DataGateway） | 信号日后首个交易日开盘价成交（含费用）；**开盘较信号日收盘低开 ≥2%（gap ≤ −0.02）→ gap_abort**（closed + close_reason=gap_abort，市场否定信号；仅 signal_day_close 可得时判断）；**超过 10 个交易日（第 11 天）无 bar → never_filled**（tracking.py 条件为 >10） |
| update_marks | 每日 close、沪深300 close | 每日记 close/ret_from_entry/ret_from_t0（相对信号日收盘）/基准/超额；维护 max_gain/max_drawdown；**全量重建，幂等** |
| close | 每日 low、开盘价 | **T+2 起每日 low ≤ entry×(1−3%) → 止损**，成交价=min(当日开盘,止损价)；或 **T+5（按信号日起数，停牌顺延）收盘平仓**；**止损优先于到期**（先把止损扫描完整个日期序列，全程未触发才看到期——非"先到先得"，tracking.py:401-428）。止损启用晚于建仓的存量仓位用 `stop_from_date` 防回溯 |

费用与整手（主文档 §7.4 `trading_rules.calc_trade_fees`）：佣金 max(0.025%, 5元) + 卖出印花税 0.05%；round_lot：主板/创业板 100 股、科创 200 股。

手动跟踪按钮 = track Job（15:40）调用**同一个** `LedgerService.ingestAndTrack()`，幂等可重跑。

## 3. 接口数据与数据库字段映射（报告信号 → 仓位行）

| 02 模块信号字段 | 仓位表列 | 说明 |
|---|---|---|
| report.as_of | `cohort_date`（+ `source_report`=scan_\<date\>） | cohort_id=scan_\<date\> |
| signal.ticker | `ticker` | |
| signal.confidence / weighted_score / screen_score | 同名列 | 供 04 复盘分桶 |
| signal.quantity / trial_cash_used | 同名列 | PM 建议股数与占用资金 |
| signal.reasons / risk_flags / analyst_summary | 同名列（JSON 原样） | 供 04 复盘按理由标签分桶 |

## 4. 入库/写入规则

- ingest/fill/marks/close 四步全部**幂等**：ingest 靠 UK(cohort_date,ticker) + active_tickers；marks 靠"全量重建"（UK(position_id,trade_date) upsert）；close 只对 open 仓位生效一次。
- 触发时机：交易日 15:40（扫描后）Quartz track Job；手动按钮同路径。
- 状态机：`pending_entry → open → closed`；gap_abort / never_filled 是 **closed + close_reason**，不新增 status 枚举值。

## 5. 后端接口

落位：`pipeline/LedgerService`（编排门面）+ `controller/LedgerController`；仓位/mark 两张业务表的分页查询走平台标准 `LedgerPositionService extends IService<LedgerPositionEntity>` + `ServiceImpl` + `Mapper`（延迟关联范式）。

> 下表路径为**前端/网关路径**（`/sniper/**`）；Controller 的 `@RequestMapping` 不带 `/sniper` 前缀（平台网关全局 StripPrefix=1，对齐 device `/category` 写法），路由在 Nacos `nqboard-gateway-dev.yml` 增加（README 全局约定）。写操作（`/track`）加 `@SysLog` + `@HasPermission`，类上 `@Tag`/`@SecurityRequirement`、方法上 `@Operation`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sniper/ledger/position` | 分页；status、closeReason、cohortDate 起止、ticker |
| GET | `/sniper/ledger/position/{id}` | 详情（含入场/止损/平仓/盈亏全字段） |
| GET | `/sniper/ledger/position/{id}/marks` | 每日 mark 序列（曲线数据：ret_from_entry / bench_ret / excess_ret 按日） |
| POST | `/sniper/ledger/track` | 手动触发 ingest+fill+marks+close；权限 `sniper_ledger_track` |
| GET | `/sniper/ledger/export` | 导出 `ledger.md`；权限 `sniper_ledger_export` |

## 6. 页面定义

### 6.1 仓位台账（6210）
- 筛选：status（三态字典，默认"在途"=pending_entry+open）、close_reason、cohort_date 区间、ticker。
- 列：cohort_date、ticker、status、entry_date、entry_price、quantity、trial_cash_used、stop_price、close_date、close_price、close_reason（四态标签：止损红/到期灰/gap_abort 橙/never_filled 灰）、pnl、pnl_pct、excess_ret、max_gain、max_drawdown。
- 行点击进详情（6211）：上半仓位全字段，下半每日 mark 折线——三条线：自入场收益、沪深300 基准、超额收益（x=trade_date）；信号日/入场日/平仓日打竖线标记。

## 7. 对拍与验收

| 项 | 方法 | 通过标准 |
|---|---|---|
| 幂等 | 同一天重复跑 ingest+track | 不重复入场、不重复 mark、已平仓不回改 |
| gap_abort | 构造 T+1 低开 ≥2% fixture | closed + close_reason=gap_abort，市场否定信号 |
| never_filled | 构造 11 个交易日无 bar（源码条件 >10，第 11 天才关闭） | closed + close_reason=never_filled |
| 止损价 | 构造 low ≤ stop_price 次日 fixture | 成交价=min(当日开盘,止损价)；`stop_from_date` 防回溯生效 |
| 影子运行 | 与 Python `track_signals.py` 同输入双跑 | 台账逐字段一致 |

## 8. 模块边界

- **上游**：02（entry_ok 信号）、01（行情经 DataGateway，止损判定必须用 none 行价格）。
- **下游**：04 复盘分析聚合本模块两张表；`market_ret_5d` 只存原始值，market_up/down 派生归 04。
- **不做**：实盘下单（本模块是纯模拟台账）；红线告警统计归 04。
