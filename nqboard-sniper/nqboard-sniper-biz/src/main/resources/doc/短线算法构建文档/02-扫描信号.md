## 2. 管线核心逻辑（本模块的"获取"是计算而非拉数）

### 2.1 端到端流程（主文档 §1.3）

```text
[定时 15:35 交易日] ScanPipeline.run()
   ├─ ① 市场门: 沪深300 近5日涨幅 < 0 → 空报告落库，结束（零 LLM/零漏斗请求）
   ├─ ② Stage0 UniverseFilter: 快照+成分+上市日期 → 9 条规则 → 候选池(~800)
   ├─ ③ Stage1 QuickScreen: 逐票 60 日 qfq 行情 → 技术特征 → 过热否决 → 快筛分 ≥35 → 排序取前 max_screen(50)
   ├─ ④ Stage2: 前 max_deep=8 只 → 数据预检 → 6 分析师并行(CompletableFuture+线程池)
   │      → trend_predictor 汇合 → risk_manager → portfolio_manager(Dify flat-decision)
   ├─ ⑤ Stage3 OutputGate: 解禁否决 + 14 条规则 → 排序 → 行业cap(1) → 每日cap(1)
   └─ ⑥ 报告/信号/被拒落库 + 渲染 Markdown（保留 reports/scan_<date>.json/.md 双产物语义）
```

阈值全部进 `SniperProperties`（主文档 §11 `sniper.strategy.*` / `sniper.gate.*`）。

### 2.2 市场门（最先执行，先于 Stage0）

沪深300 最近 5 个交易日涨幅（6 根收盘K线）< `market.minRet=0.0` → 直接落库空报告（`market_gate_blocked=1`），跳过一切后续。代码默认开关 false，**Java 版默认 true 并在配置注明出处**（2026-09 台账复盘：五日下跌批次胜率仅 28.6%）。

### 2.3 Stage0 池过滤（9 条全过才保留）

| # | 规则 | 参数 |
|---|---|---|
| 1 | 代码可提取 6 位数字 | — |

### 2.4 Stage1 快筛（纯规则，~800 票）

1. 逐票取 60 交易日 qfq 行情（库优先）；**<30 根 → 淘汰**。
2. `TechnicalFeatureCalculator`（纯函数，`algorithm.indicator` 包，`features/technical.py` 1:1）：EMA5/10/20、MACD(12,26,9)、RSI6/14（**简化版：涨跌单侧滚动均值；单侧为零映射为极值——全涨→100、全跌→0；仅当涨跌都为 0（窗口内无波动）才返回 50**——防钝化关键）、momentum_5d、volume_ratio=mean5/mean20、20日突破（≥0.995×20日高）、volatility_20d（√244 年化）、ma_ratio、gap_open_pct、涨停族特征（板块动态限值±0.1%容差）、**trend_strength**（`0.30*ema+0.25*macd+0.20*rsi+0.15*mom+0.10*vol`，clamp[-1,1]）。
3. 过热否决（与 gate 共用同一 Bean）→ 命中即淘汰。
4. 快筛打分表（逐条照抄 `quick_screen.py`；阈值常量在 `short_metrics.py`）：EMA排列+25/−5/+10、MACD金叉+10、动量×量比+20（1%~8% 且量比≥1.2）/+10（0.5%~1%）/+3（>8%）/−5（<−8%）、量比+15（≥1.5）/+8（≥1.2）、RSI +10（25~40）/+15（40~70）/+8（≤25）/−3（≥75）、突破+15（且量比≥1.5）/+5、趋势强度+15（>0.3）/+8（>0.1）/−8（<−0.2）、市场环境+10（market_ret_5d>−2%）/−5（<−4%）、连板惩罚−15（≥2 连板且今日仍封板））→ `<35` 淘汰。
5. 全候选按分降序取前 `max_screen`——**Java 配置默认 50**（Python CLI 默认 30、每日命令行传 50，Java 取 50 与日常运行对齐）。

### 2.5 Stage2 数据预检（进 LLM 前最后一道）

| 项 | 必需 | 失败 |
|---|---|---|
| 行情 ≥60 根（`max(30, lookback)`） | 是 | 拒因 `prefetch:prices` |
| 新闻接口可达（0条仅告警） | 是 | 拒因 `prefetch:news_fetch` |

拒因兜底：预检失败但列不出缺失项时用 `prefetch:failed`。

### 2.7 分析师编排（主文档 §7.1）

分析师集合 = SHORT_TERM_ANALYST_KEYS：technical / sentiment / main_force_flow / dragon_tiger / sector_rotation / policy_sentiment + trend_predictor（短画像用 main_force_flow 替代 northbound_flow）。Java 17 无虚拟线程，用 CompletableFuture + 专用线程池：

```java
// 规模下限 = 分析师数(6)；跨票并行时按 6×max_deep=48 配置（详见主文档 §7.1）
var ex = Executors.newFixedThreadPool(12);
var futures = analysts.stream()
        .map(a -> CompletableFuture.runAsync(() -> a.analyze(ctx), ex))
        .toList();
CompletableFuture.allOf(futures.toArray(CompletableFuture[]::new)).join(); // 6 路并行
trendPredictor.analyze(ctx);   // 汇合：读前6家
riskManager.analyze(ctx);
portfolioManager.analyze(ctx); // flat: 规则合成 + 可选 Dify W3
```

`AnalysisContext`：`Map<agentId, Map<ticker, SignalPayload>> analystSignals` + `Map<ticker, RiskResult> riskResults` + metadata（model/mode/asOf/trialCash）。`SignalPayload` = `{signal: bullish|bearish|neutral|n/a, confidence: 0-100, reasoning: {...}}`（gate 只深挖 `technical.reasoning.composite_metrics`）。

### 2.8 七分析师规则速查（公式/阈值照主文档 §7.3）

| Agent | 数据(gateway 方法) | 规则要点 | LLM |
|---|---|---|---|
| technical | getPrices(60日 qfq) | 4子策略加权：趋势0.35(EMA排列+ADX14≥20) / 动量0.30(ret5 1~8%+量比>1.2；>8%弱多0.35) / 超买超卖0.20(RSI6<25且z<−1.5多；>75且z>1.5空) / 突破0.15(≥0.995×20日高+量比>1.5)；score=Σ(值×权重×conf)/Σ(权重×conf)，>0.2 bullish，conf=\|score\|×100；**输出 composite_metrics 全量** | 否 |
| sentiment | getInsiderTrades(1000) + getCompanyNews(100) | insider 0.3(减持=空) + news 0.7(LLM=W1 批量分类前5条；无LLM用关键词预打标)；失败→n/a（fail-closed：news 腿占 0.7，缺失不得静默合成） | W1 |
| main_force_flow | getMainFundFlow(5日) | threshold=max(\|均值\|×0.8, 1元)；连续流入≥2日且3日净额>threshold→bullish conf=min(85,50+min(连续,4)×8+min(net3d/均值,3)×5)；对称空；仅3日净额越阈→55；否则 neutral 48；缺失→neutral 40（不拒票）；超大单占比>0.3 同向 +5（cap 88） | 否 |
| dragon_tiger | getDragonTiger(30日) | 近5日上榜≥2且净买>0→bullish conf=min(85,60+次数×5+min(净买/1e8,5)×4)；上榜≥1且净买>0且买/卖比>1.3→bullish conf=min(75,55+min(净买/1e8,3)×5)；净买<0→bearish conf=min(78,55+min(\|净买\|/1e8,5)×5)；上榜≥1但净买≈0→neutral 50；近30日上榜但近5日无→neutral 45；未上榜→neutral 40；原因关键词同向 +4（cap 88） | 否 |
| sector_rotation | getStockIndustry + getIndustryBoardHist | 板块3日涨幅>1%→bullish(<−1%空) conf=min(85,52+\|ret\|×400+同向+8)；**板块缺失→neutral 40，禁止用个股涨幅替代** | 否 |
| policy_sentiment | getCompanyNews(50)+14关键词预筛 | 有政策新闻+LLM模式→W2；失败→n/a；无/少政策新闻→neutral 40 | W2 |
| trend_predictor | 前6家信号 + getPrices/getFinancialMetrics/flow特征/短结构 | score=0.40×trend_strength+0.05×基本面+0.15×情绪+0.20×资金流+0.05×分析师均值+0.15×连板结构（`rule_ensemble.py` SHORT_WEIGHTS）；≥0.15→up（≤−0.15 down） | 否 |

**risk_manager**（非信号型）：60日收益率 → 年化波动（√244）→ vol_multiplier（<15%→1.25；15~30%→1−(v−0.15)×0.5；30~50%→0.75−(v−0.30)×0.5；>50%→0.5；夹[0.25,1.25]，基线仓位20%）× corr_multiplier（均值相关 ≥0.8→0.70 / ≥0.6→0.85 / ≥0.4→1.00 / ≥0.2→1.05 / <0.2→1.10）。输出 `remainingPositionLimit = min(上限−现持仓市值, 现金)`；**PM 建议股数 = limit ÷ price 向下取整手**（主板/创业板100，科创200），费用=佣金 max(0.025%,5元)+卖出印花税0.05%。

**portfolio_manager**（flat 合成，`decision.py` SHORT_TERM_ANALYST_WEIGHTS：technical .30 / main_force .15 / dragon .10 / sentiment .10 / sector .15 / policy .10 / trend .10；n/a 整项剔除；`+0.15×trend_strength` 后 clamp ±1）：
- score ≤ **−0.20** → avoid（conf=min(90, 55+|score|×40)）
- score ≥ **0.35** 且 buy 可交易 → entry_ok（conf=min(95, 55+score×45)；score<0.5 时数量减半）
- ≥0.35 但不可买 → watch（block_reason=涨停/停牌/资金不足）
- 其余 → watch（conf=55）；**永不输出 sell**
- decision_mode=llm 时走 W3，失败全部降 watch。

### 2.9 Stage3 Gate（输出门禁，主文档 §8）

主流程：`解禁否决(逐票) → passesGate(14条,全评估不短路) → BuySignal 落库 → 按(confidence, weighted_score)降序 → 行业cap(1,留最强,余 industry_cap) → 每日cap(1,余 daily_cap)`。行业标签拿不到时 **fail-open 放行**，拒因写 `industry_cap:<industry>>1`。

**过热否决 `overheatVeto(metrics)`**（Stage1 与 gate 共用同一 Bean）：RSI6 ≥ 90 / momentum_5d > +4.5% / < −1% / trend_strength > 0.46 → 拒（4.77 万样本挖掘依据）。gate 侧仅在 composite_metrics 非空时执行（缺失跳过，不拒）。

**十四条规则与拒因（枚举 `RejectReason`，`code()` 必须逐字节一致）**：

| # | 检查 | 参数 | code() |
|---|---|---|---|
| 1 | 市场门二道 | ret_5d<0 | `market_env_weak:ret_5d=%s<%s` |
| 2 | 解禁否决 | 7天内≥5%（比值>1.5自动按百分比归一） | `restricted_release_within_7d:%.1f%%` |
| 3 | PM 必须 entry_ok | — | `action=%s` |
| 4 | 可交易 | — | `not_tradable` |
| 5 | 置信度 | ≥70（校准开关默认关；开启时拒因尾部追加 `" (calibrated)"`） | `confidence=%s<%s` |
| 6 | 加权得分 | **停用**（阈值0，保留代码路径） | `weighted_score=%s<%s` |
| 7 | LLM 硬失败 | 深度遍历7个payload（含 reasoning JSON 字符串）找 fallback/llm_mode=llm_error 或 signal=llm_error | `llm_unavailable:<agent>`（agent 名去 `_agent` 后缀） |
| 8 | 趋势/技术双条件 | trend up **或** \|trend_strength\|>0.3 | `trend_not_up_and_tech_weak` |
| 9 | 技术置信度 | ≥50 | `technical_confidence=%s<50` |
| 10 | 过热否决 | §2.9 过热 | `overheated_rsi6=%s>=90` / `overheated_momentum_5d=%s>4.5%%` / `underwater_momentum_5d=%s` / `overextended_trend_strength=%s` |
| 11 | 非趋势须有真趋势 | trend非up时 ADX≥25 | `flat_trend_adx=%s<25` |
| 12 | 偏多分析师≥3 | 分组计数（价格组cap 2），n/a 不算 | `bullish_agents=%d<3` |
| 13 | 价格组≥1 | technical/trend/sector 最多计2 | `price_group_bullish=%d<1` |
| 14 | 资金情绪组≥1 | main_force/dragon/sentiment/policy | `fund_sentiment_bullish=%d<1` |

其余拒因（+6）：`no_decision` / `prefetch:prices` / `prefetch:news_fetch` / `prefetch:failed` / `industry_cap:%s>%s` / `daily_cap:%s`。14 条规则派生 17 个模板 + 6 = 合计 **23 个**——枚举落在 `nqboard-sniper-api` 的 `enums/RejectReasonEnum`，sys_dict 的 `sniper_reject_reason` 与之同源，CI 契约测试锁死（主文档 D5）。动态部分与格式化精度（`%.4f`/`%.1f`/`%.0f`、`{days}` 默认 7、`daily_cap:{cap}` 默认 1 等）按主文档 §8.3 契约注拼接。

## 3. LLM 调用（Dify 三工作流）

全系统 LLM 调用点只有 3 类，全部做成 Dify Workflow（建法与 prompt 原文见主文档 §6.2~6.4，模型 `glm-5.3`、temperature=0.1、开启 JSON 输出）：

| 工作流 | 输入 | 输出 schema | 失败语义 |
|---|---|---|---|
| W1 `news-sentiment-batch` | ticker + headlines（编号文本行，最多 5 条） | `{"items":[{"index","sentiment","confidence"}]}` | 缺失条目回填 neutral（index 越界丢弃）；空/None → 整体失败 |
| W2 `policy-sentiment` | ticker + 政策关键词预筛新闻（14 词表照 `_POLICY_KW`） | `{"signal","confidence","reasoning"}` | 无/少政策新闻时 Java **不调用**（直接规则 neutral 40） |
| W3 `flat-decision` | context（JSON，键=ticker，含 weighted_score/allowed_actions/tradable/block_reason/**完整规则决策对象 rule_suggestion**） | `{"decisions":{TICKER:{action,quantity,confidence,reasoning,tradable,block_reason,weighted_score}}}` | 规则版兜底但**全部 entry_ok 强制降级 watch**，`block_reason=llm_unavailable` |

Java 调用契约（`DifyClient`）：`POST {dify.base-url}/v1/workflows/run`，Bearer app-xxx，`response_mode=blocking`，超时 90s、重试 3 次（退避 2n+rand s），重试耗尽抛 `LlmCallException`。**fail-closed 失败语义表（全系统一致，主文档 §6.5）**：

| 场景 | Java 处理 | 下游效果 |
|---|---|---|
| HTTP 非 200 / 超时 / 网络错误 | 重试3次 → `LlmCallException` | agent payload `signal="n/a", confidence=0, reasoning.fallback="llm_error"` → gate 拒票（`llm_unavailable:<agent>`） |
| 200 但 outputs 非法/字段缺失 | 同上（`parse_error`） | 同上 |
| W3 失败 | 规则版兜底全降 watch | gate 全拒，报告可见 |
| Dify 的"看似合理"默认值 | **一律不信**（`CN_LLM_FAIL_HARD=true` 语义） | — |

W3 强制后处理：`tradable=false` 一律改写 `watch`；quantity ≤ allowed 且整手（超界改写）。每次调用（成功/失败）写 `sniper_llm_call_log`（05 模块的表）。调用量：8 只 deep 票 = 情绪 8 + 政策 ≤8 + flat 合成 1 = **≤17 次/扫描**。

## 5. 后端接口

落位：`pipeline/ScanPipeline` + `algorithm/{indicator,funnel,agent,gate}`（纯算法域，零 Spring 依赖可单测）+ `llm/DifyClient` + `controller/ScanController`。报告/信号/被拒的分页查询走平台标准 `ScanReportService` 等实体 Service（延迟关联范式），ScanPipeline 只做编排与落库。

> 下表路径为**前端/网关路径**（`/sniper/**`）；Controller 的 `@RequestMapping` 不带 `/sniper` 前缀（平台网关全局 StripPrefix=1，对齐 device `/category` 写法），路由在 Nacos `nqboard-gateway-dev.yml` 增加（README 全局约定）。

## 6. 页面定义

### 6.1 扫描报告（6110）
- 列表：as_of、universe、market_gate_blocked（拦截标记醒目展示）、stage0/1/2_count、signal_count、prefetch_ok；默认 as_of 倒序。
- 操作：行点击进详情（6114 隐藏路由）；页头"手动扫描"按钮（弹窗选 universe 四档，提交后轮询 `sniper_daily_run` 状态）；"指定票复查"按钮（粘贴 ticker 列表）。
- 详情页：Tab1 Markdown 报告（渲染 `report_md`）；Tab2 JSON 原文（`report_json` 折叠树）；Tab3 漏斗统计（meta：预算/漏斗计数/prefetch_warnings）。页内导出按钮（md/json）。

### 6.2 信号明细（6120）
- 筛选：reportId、ticker、action（三态字典）。
- 列：ticker、action（颜色区分 entry_ok 绿/watch 灰/avoid 红）、confidence、weighted_score、quantity、trial_cash_used、reasoning、screen_score。
- 行展开：reasons（偏多因子标签）、risk_flags、analyst_summary（8 家 signal/confidence 表格化）、prefetch_warnings。

### 6.3 被拒明细（6130）
- 顶部：拒因分组统计条（23 拒因 × 计数，横向条形，点击即按该拒因过滤列表）——复盘对账核心入口。
- 筛选：reportId、ticker、reason。
- 列：ticker、reasons（标签列表）、decision（PM 决策对象摘要）、warnings。
- 行展开：decision/warnings 完整 JSON。

## 7. 对拍与验收（主文档 §12）

| 层级 | 方法 | 通过标准 |
|---|---|---|
| 指标级 | 构造已知 K 线（含除权跳空、一字板、连板、单侧涨跌）断言 EMA/MACD/RSI(单侧零→极值)/ADX/涨停特征 | 逐位相等（BigDecimal 容差 1e-9） |
| 漏斗级 | 同一份 MySQL 数据跑 Python quick_screen 与 Java QuickScreen | Stage0/1 产出票集与 screen_score 完全一致 |
| gate 级 | 20+ 组 analyst_signals fixture 表驱动断言 | passed+拒因集合与 Python 逐条一致（含 code() 字节级） |
| 报告级 | golden master：同输入 Java 输出 diff Python `reports/scan_<date>.json`（除时间戳/耗时） | 零差异 |
| LLM 级 | WireMock 模拟 Dify 正常/超时/非法 JSON 三态 | fail-closed 行为正确 |

## 8. 模块边界

- **上游依赖**：01 数据资产（DataGateway 全量消费）；Dify 平台（3 工作流，密钥在 Nacos）。
- **下游消费**：03 信号台账 ingest 本模块报告的 entry_ok 信号；05 运维监控的 LLM 审计页/请求审计页展示本模块运行时写入的日志。
- **不迁移清单（勿在此模块"顺手实现"）**：14 个名人/全画像 agent、legacy 交互 CLI、`app/` FastAPI Web UI、北向资金分析师、`src/backtesting/` + `src/backtester.py` 回测/ML 管线、`--intraday` 盘中模式。
- 手动复查（`/sniper/scan/recheck`）复用 Stage2 深度分析代码路径，但**绝不写台账**。
