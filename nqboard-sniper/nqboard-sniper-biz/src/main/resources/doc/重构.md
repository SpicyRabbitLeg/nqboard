## 1. 系统全景

### 1.1 业务定位

A 股短线（T+1 买入、持有 5 个交易日）买入信号系统。空仓（flat）账户、10 万试仓资金。每日盘后跑一次漏斗扫描 + 多 Agent 证据合成 + 硬性门槛（gate），产出 0~1 只（`CN_SCAN_MAX_SIGNALS_PER_DAY=1`）entry_ok 信号，并自动进入模拟台账跟踪胜率。

设计哲学（重构必须保留）：

1. **宁缺毋滥**：gate 是"全部通过才发信号"的白名单，任何一项不过即整票拒绝，且拒绝原因必须可解释（写入报告 `rejected` 表）。
2. **证据不完备即 fail closed**：LLM 挂了、行情不足、数据缺失的票一律拒绝，绝不静默降级后发信号（`CN_LLM_FAIL_HARD=true`）。
3. **门槛参数全部来自复盘数据**：过热否决（RSI6/动量/趋势强度）、市场门、负 IC 停用加权得分等，都源自 `reports/research/mining_2026-09-15.md`（4.77 万样本回放）与台账分桶复盘，不是拍脑袋。

### 1.2 每日两条命令

```bash
# ① 盘后扫描（15:30 后）
poetry run python scripts/scan_buy_signals.py \
  --universe hs300_csi500 --model glm-5.3 \
  --max-deep 8 --max-screen 50 --trial-cash 100000 \
  --verbose --output reports/scan_all.json

# ② 信号跟踪（扫描完接着跑）
poetry run python scripts/track_signals.py --output reports/track.json --verbose
# 复盘（随时/每周）：track_signals.py --review
```

产物：

| 文件 | 生成方 | 说明 |
|---|---|---|
| `reports/scan_<数据日>.json/.md` | scan_buy_signals.py | 扫描报告（输出文件名按 `as_of` 自动改名） |
| `data/signal_tracking/ledger.json` | track_signals.py | 模拟台账（幂等） |
| `reports/ledger.md` | track_signals.py | 台账人读视图（每次刷新全量） |
| `reports/track_<今天>.json/.md` | track_signals.py | 跟踪日报 |
| `reports/review_<今天>.md` | track_signals.py --review | 分桶复盘 |
| `data/cache/<category>/*.json` | daily_cache | 当日数据缓存 |
| `data/cn_trade_calendar.json` | calendar | 交易日历磁盘缓存 |

### 1.4 端到端流程（扫描）

```
scan_buy_signals.py
  ├─ resolve_as_of_date()        非交易日回退上一交易日（日历）
  ├─ fetch_market_ret_5d()       沪深300 5日涨幅（get_prices("000300.SH")）
  ├─ 市场门: ret_5d < CN_SCAN_MARKET_MIN_RET(0.0) → 直接输出空报告，结束（不耗任何LLM/数据请求）
  ├─ [Stage 0] resolve_universe_codes() → hs300∪csi500 成分码
  │            fetch_a_share_spot() → 全市场快照 → filter_universe()（流动性/ST/板块/次新/涨停过滤）
  ├─ [Stage 1] quick_screen()：逐票 get_price_data(60日) → compute_technical_features
  │            → 过热否决 + 技术打分（≥35 分）→ 按分排序取 top --max-screen(50)
  ├─ [Stage 2] 取前 --max-deep(8) 只 → prefetch 数据预检 → run_flat_short_analysis():
  │              LangGraph: 6 分析师并行 → trend_predictor → risk_manager → portfolio_manager
  │              （sentiment/policy 走 LLM，PM 空仓合成走 LLM，其余纯规则）
  ├─ [Stage 3] apply_output_gate()：解禁检查 + passes_gate 逐票裁决
  │            → 按置信度排序 → 单行业 cap(1) → 单日 cap(1)
  └─ 输出 scan_<date>.json / .md（含 signals + rejected + 预算/漏斗统计）
```

## 2. 数据获取层（现状规格）

### 2.1 分层架构

```
调用方 (agents / scan / tracking)
        │  只认 src/tools/api.py 的函数
        ▼
tools/api.py  ── 数据门面：缓存查询（内存 Cache → daily_cache 磁盘）→ 未命中则调 provider
        ▼
providers/composite.py  CompositeCNProvider —— 路由层
  │  CN_DATA_PROVIDER=tushare 且 TUSHARE_TOKEN 存在 → 行情 Tushare 优先
  │  CN_TUSHARE_FIRST=true → 非行情端点也 Tushare 优先（失败/空 → AkShare 兜底）
  ▼
providers/akshare_provider.py      providers/tushare_provider.py
        │                                   │
akshare_client.py                   tushare_client.py
  (akshare SDK + 东财 push2 直连)      (tushare SDK pro_api)
        │
web_fallback.py  —— 最后的 HTTP 直连兜底（腾讯 ifzq/qt.gtimg、新浪 quotes/hq.sinajs、
                    东财 push2/push2his/push2delay/push2ex/search-api-web）
```

关键路由事实（当前 `.env`：`CN_DATA_PROVIDER=tushare`、`CN_TUSHARE_FIRST=true`、`TUSHARE_TOKEN` 已配置）：

| 端点 | 实际主源 | 兜底 |
|---|---|---|
| 个股/指数日行情 | Tushare `pro_bar`/`index_daily` | AkShare `stock_zh_a_hist` → 东财直连 K线 → 腾讯 → 新浪 |
| 财务指标（基本面） | AkShare（同花顺 `stock_financial_analysis_indicator`） | 无（Tushare 只补估值字段） |
| 估值字段 PE/PB/市值 | Tushare `daily_basic`（与上面合并） | — |
| 新闻/行业板块K线/盘口快照/涨跌停池 | AkShare（Tushare 无等价接口） | 东财直连 → 腾讯/新浪 |
| 主力资金流/龙虎榜/解禁/两融/增减持 | Tushare（`CN_TUSHARE_FIRST=true`） | AkShare |
| 行业分类 | 东财直连（`get_stock_industry_em`，与板块名对齐） | Tushare `stock_basic` → AkShare info |
| 全市场快照 | AkShare `stock_zh_a_spot_em` | `stock_zh_a_spot` → 新浪 Market_Center → 腾讯批量 |
| 指数成分 | Tushare `index_weight`（最新快照日） | 中证指数官网 csindex（AkShare 封装） |
| 交易日历 | 磁盘缓存 → Tushare `trade_cal` | AkShare `tool_trade_date_hist_sina` → 工作日近似 |

### 2.2 缓存体系（三层 + 模块级散缓存）

| 层 | 位置 | Key 例 | 生命周期 | 说明 |
|---|---|---|---|---|
| 内存合并缓存 | `src/data/cache.py`（全局单例） | `cn_qfq_600519.SH_2026-07-01_2026-09-26` | 进程内，**只增不减**（按 time/report_period 等字段去重合并） | prices/financial_metrics/line_items/insider/news 五类 |
| 当日磁盘缓存 | `src/data/daily_cache.py` | `data/cache/prices/<key>.json`，内部存 `cache_date` | 当天有效（UTC+8 日期戳），`CN_DAILY_CACHE_ENABLED=true` | 同一天重复扫描不重复拉行情；categories: prices/financial_metrics/insider_trades/company_news/northbound/industry_board/spot/index_constituents |
| 门面 DF 缓存 | `tools/api.py::_df_cache` | `nb_<ticker>` / `mf_<ticker>` / `lhb_<ticker>_<days>` / `margin_<date>` / `mb_...` / `rr_<ticker>` / `auct_<ticker>` / `board_<行业>` / `limit_pool_<kind>_<date>` | 进程内（**无 TTL**） | DataFrame 级 |
| 模块级散缓存 | `akshare_client.py`：`_stock_info_cache`、`_market_cache`（LHB 区间/两融日期/涨跌停池共用）、`_ths_board_names_cache`；`tushare_client.py`：`_trade_dates_cache`、`_stock_codes_cache`、`_listing_dates_cache`、`_industry_map_cache`、`_hk_hold_cache`、`_top_list_cache`、`_margin_cache` | — | 进程内（无 TTL） | 全市场型接口按日期/区间缓存一次，逐票本地过滤 |

> 重构注意：`_df_cache` 与各模块散缓存**从不清理**，长驻进程会无限增长且隔日数据陈旧；CLI 每日一次性运行尚可接受，Web/常驻服务场景必须改（见 P-03）。

### 2.3 限流 / 重试 / 熔断 / 预算

| 机制 | 参数（当前值） | 实现位置 |
|---|---|---|
| AkShare 全局节流 | 最小间隔 `AKSHARE_REQUEST_DELAY_SECONDS=2.0`（代码下限 0.5s），进程级互斥锁 | `market/cn/rate_limit.py::throttle` |
| AkShare 重试 | `AKSHARE_MAX_RETRIES=5` 次，退避 `2.0s*(n)+rand(0,1)` | `run_throttled_retry` |
| 东财熔断 | 连接类错误（RemoteDisconnected 等 7 种标记）→ 熔断 `EM_CIRCUIT_BREAKER_SECONDS=300` 秒，期间直接走腾讯/新浪兜底 | `akshare_client.py::_run_em_retry` |
| Tushare 节流 | `TUSHARE_REQUEST_DELAY_SECONDS=0.35`（≥2000积分档） | `tushare_client.py::_throttle` |
| Tushare 重试 | `TUSHARE_MAX_RETRIES=3`，限频错误退避 `2*(n)`s，其他 `1*(n)`s，+rand(0,1) | `_call` |
| 每日请求预算 | `CN_SCAN_MAX_AKSHARE_REQUESTS=300`；**仅 AkShare 主源模式生效**（`tushare_preferred_for_prices()` 为真时不消耗）。快照=1、每个指数成分=1、Stage1 每票=1、市场环境=1；耗尽后 Stage1 跳票并记 `stage1_skipped_due_to_budget`，报告 meta 带出 | `scan/rate_budget.py` |
| 请求追踪 | 环境变量 `CN_REQUEST_LOG=<jsonl路径>` 开启；每行 `{ts, endpoint, source, params, status, n_rows, summary, error, elapsed_ms}` | `data/request_log.py`（composite/providers/client 各处埋点） |

### 2.4 外部接口清单（逐个：入参 → 出参）

> 以下为**实际生效**的实现（`akshare_client.py` 中同名函数被定义多次，Python 后定义覆盖前者——这是 P-01 问题；此处以文件末尾的生效版本为准）。出参列到"下游消费字段"粒度。

#### 2.4.1 日行情（个股）—— `akshare_client.get_prices(ticker, start_date, end_date, adjust=None) -> list[Price]`

| 级别 | 上游 | 入参 | 出参（→ Price 字段） |
|---|---|---|---|
| 1 | Tushare `pro_bar`（composite 路由，个股）/ `index_daily`（000300/000905/399006） | `ts_code="600519.SH"`, `adj=hfq|qfq|None`, `start_date=YYYYMMDD`, `end_date=YYYYMMDD`, `freq="D"` | DataFrame `trade_date, open, close, high, low, vol` → `Price(open, close, high, low, volume=int(vol), time=YYYY-MM-DD)`，按日期升序 |
| 2 | AkShare `ak.stock_zh_a_hist(symbol=6位码, period="daily", start_date=YYYYMMDD, end_date=YYYYMMDD, adjust=""/qfq/hfq)` | 同上（`""`=不复权） | DataFrame `日期/开盘/收盘/最高/最低/成交量` → Price |
| 3 | 东财直连 `GET https://push2his.eastmoney.com/api/qt/stock/kline/get` | `secid={1|0}.{code}`（1=沪 0=深）、`fields1=f1..f6`、`fields2=f51..f61`、`klt=101`、`fqt={0,1,2}`、`beg/end=YYYYMMDD`；浏览器 UA 头 `_EM_HEADERS` | `data.klines`（CSV 行字符串）→ 解析为 日期/开盘/收盘/最高/最低/成交量 |
| 4 | 腾讯 `GET https://web.ifzq.gtimg.cn/appstock/app/fqkline/get`（param=`sh600519,day,start,end,<count>,hfq`） | ticker、区间、adjust | K线数组 → Price（复权） |
| 5 | 新浪 `GET https://quotes.sina.cn/cn/api/json_v2.php/CN_MarketDataService.getKLineData?symbol=sh600519&scale=240&ma=no&datalen=...` | ticker、区间 | K线数组 → Price（**不复权**，日志会 warning "UNADJUSTED"） |

### 3.1 Stage 0 池过滤 `filter_universe(spot_df, allowed_codes, config)`

| 2 | 须在 allowed_codes（指数成分）内 | `--universe` 决定 |

### 3.2 Stage 1 快筛打分 `quick_screen(candidates, as_of, top_n, budget)`

对每只候选（串行）：

1. 预算检查（AkShare 主源模式时每票消耗 1；耗尽则记 skip 并截断）。
2. `get_price_data(ticker, lookback_start(as_of, 60), as_of)` —— **60 个交易日**窗口（`CN_SHORT_LOOKBACK`）。
3. **硬性数据门槛**：K线为空或 **< 30 根** → 直接淘汰（EMA20/MACD(12,26,9)/BOLL20 预热不足，同时天然过滤次新）。
4. `compute_technical_features(df, profile="short", ticker)` 计算特征（见 3.3）。
5. **过热否决 `overheat_veto_reason`**（与 Stage 3 gate 共用同一函数，规则见 5.3）——命中即淘汰（日志 `quick_screen veto`）。
6. 技术打分（下表），低于 `CN_SCAN_MIN_SCREEN_SCORE=35` 淘汰。
7. 全部候选按分数降序，取前 `--max-screen`（默认 30，SOP 用 50）。

**快筛评分表（满分无上限，典型 40~90）**：

| 维度 | 条件 | 分值 |
|---|---|---|
| EMA 排列 | ema5>ema10>ema20（多头） | +25 |
| | ema5<ema10<ema20（空头） | −5 |
| | 非多头但 ma5/ma20−1 > 0 | +10 |
| MACD | 今日金叉（hist 今日>0 且昨日≤0） | +10 |
| 动量（5 日涨幅 mom5 × 量比确认） | 1%≤mom5≤8% 且 量比≥1.2 | +20 |
| | 0.5%≤mom5<1% | +10 |
| | mom5>8%（追高风险） | +3 |
| | mom5<−8%（放量大跌） | −5 |
| 量比（5日均量/20日均量） | ≥1.5 | +15 |
| | ≥1.2 | +8 |
| RSI6 区间 | 25<RSI<40（超卖反弹区） | +10 |
| | 40≤RSI≤70（健康上升区） | +15 |
| | RSI≤25（深度超卖） | +8 |
| | RSI≥75（超买） | −3 |
| 20 日突破 | 收盘≥0.995×20日最高 且 量比≥1.5 | +15 |
| | 仅突破 | +5 |

产出 `ScreenCandidate(ticker, name, screen_score, metrics{momentum_5d, ma_ratio, volume_ratio, rsi_6, trend_strength, ema_align, macd_hist, breakout_up, consecutive_limit_up, limit_up_distance_pct})`。`screen_score` 随信号写入台账供复盘分桶（<40/40-50/50-60/60+）。

### 3.3 技术特征 `compute_technical_features(df, profile="short", ticker)`（`src/prediction/features/technical.py`）

输入：`prices_to_df` 产物（index=Date，列 open/close/high/low/volume）。数据 <10 根 → 返回空特征 + `_gaps=["insufficient_price_history"]`。

**基础量**（全部基于 close 序列，`ewm(span=N, adjust=False)`）：

- EMA5/10/20；`ema_align` = ema5>ema10>ema20（1.0）；`ema_bear_align` 反向（−1.0）；`ema_spread = close/ema20 − 1`。
- MACD(12,26,9)：dif=ema12−ema26；dea=dif 的 EMA9；hist=(dif−dea)×2；`macd_gold_cross` = hist 今日>0 且昨日≤0。
- RSI6/RSI14：**Wilder 简化版**（rolling mean 的 gain/loss），且**单侧为零映射为极值**（全涨→100、全跌→0，绝不映射 50——防掩盖 blow-off top）。
- `momentum_5d = close.pct_change(5)`；`momentum_20d` 同理。
- `volume_ratio = mean(vol[-5:]) / mean(vol[-20:])`。
- 20 日突破：`breakout = close/max(high[-20:]) − 1`；`breakout_up = close ≥ 0.995×max(high20)`。
- `volatility_20d`：日收益率 std × √244（`CN_ANNUAL_TRADING_DAYS`）。
- `ma_ratio = ma5/ma20 − 1`；`vwap_dev`（5 日典型价加权）；`gap_open_pct = 今开/昨收 − 1`。
- 涨停相关（按板块动态限值：主板 10%/创业科创 20%/北交 30%/ST 5%，容差 0.1%）：`consecutive_limit_up`（≤5 日回溯连续封板数）、`is_limit_up_today`、`limit_up_distance_pct = (昨收×(1+限值) − 收盘)/收盘`。

**复合趋势强度（核心输出，[−1,1]）**：

```
ema_score  = 多头排列: min(1, |ema_spread|*5) ；空头排列取负；否则 sign(spread)*min(|spread|*3, 0.5)
macd_score = clip(hist/close * 50, -1, 1)
rsi_score  = clip((rsi_6 - 50)/30, -1, 1)
mom_score  = clip(sign(ret5)*min(|ret5|*10, 1), -1, 1)
vol_score  = clip((vol_ratio-1)/1.5, -0.5, 1)；若 ret5<0 则取负（放量下跌为负）
trend_strength = clip(0.30*ema_score + 0.25*macd_score + 0.20*rsi_score + 0.15*mom_score + 0.10*vol_score, -1, 1)
```

**短结构特征**（`features/short_structure.py`，仅 trend_predictor 用）：连板结构分（首板 1.0 > 2 板 0.7 > 3 板 0.4 > ≥4 板 0.1；未封板但有连板记忆 0.2）×0.30 + 高开×0.20 + 换手×0.20 + 板块相对强度×0.15 + 封板强度×0.15 → `short_structure_score ∈ [−1,1]`。

### 3.4 Stage 2 数据预检 `prefetch_short_profile_data(tickers, start, end)`

对每只 deep 票（进入 LLM 分析**之前**执行）：

| 检查项 | 必需? | 判定 | 失败后果 |
|---|---|---|---|
| 行情 | **必需** | `get_prices(ticker, lookback_start(end, 70), end)` 条数 ≥ max(30, 60)=60 | `result.ok=False`，拒因 `prefetch:prices`，不进 LLM |
| 新闻拉取 | **必需**（接口不抛错即可，0 条仅 warning） | try `get_company_news(limit=50)` | 拒因 `prefetch:news_fetch` |
| 增减持 | 可选 | try | warning"高管增减持数据不可用" |
| 北向 | 可选 | 解析 tail(5) ≥2 条 | warning"北向资金数据不足" |
| 行业+板块 | 可选 | industry 有值再拉 board | warning"行业分类不可用" |

失败票进入 `rejected`（`run_flat_short._prefetch_rejections`），其余票继续。所有 warning 汇总进 `prefetch_warnings[ticker]` 并写入报告。

             ├─ dragon_tiger_agent        （纯规则）
             ├─ sector_rotation_agent     （纯规则）
             └─ policy_sentiment_agent    （LLM: 政策舆情）
                    ↓ 全部完成后
             trend_predictor_agent        （纯规则，读前面所有 analyst_signals）
                    ↓
             risk_management_agent        （纯规则：波动率×相关性仓位上限）
                    ↓
             portfolio_manager            （LLM: 空仓合成 generate_flat_decision_llm）
                    ↓ END
```

State（`graph/state.py::AgentState`）：`data.tickers/start_date/end_date/portfolio/analyst_signals{agent→{ticker→payload}}` + `metadata{model_name, model_provider, decision_profile="short", account_mode="flat", decision_mode, sentiment_mode, show_reasoning}`。每个 analyst 把结果写入 `state["data"]["analyst_signals"][agent_id]`。

决策模式解析（`scripts/scan_buy_signals.py::_resolve_model`）：`--model glm-5.3` 在 `api_models.json` 命中（provider=Zhipu）→ `decision_mode="llm"`、`sentiment_mode="llm"`；**不传 `--model` 则全程纯规则（零 LLM 调用）**。

### 4.2 七个分析师逐一规格

以下 payload 结构即 `analyst_signals[agent][ticker]`，也是 gate/PM/报告的输入。

#### ① technical_analyst_agent（纯规则，`agents/technicals.py::_analyze_short`）

输入：`get_prices`（qfq）→ DataFrame。四个子策略加权合成：

| 子策略 | 权重 | 规则要点 |
|---|---|---|
| short_trend | 0.35 | EMA5/10/20 多头排列且 ADX14≥20 → bullish（conf=min(adx/50,1)）；空头排列且 ADX≥20 → bearish；仅 ema5>ema20 → bullish 0.4；ema5<ema20 → bearish 0.4；其余 neutral 0.5 |
| short_momentum | 0.30 | 1%≤ret5≤8% 且量比>1.2 → bullish conf=min(|ret5|×8,1)；ret5>8% 放量 → 弱多 0.35（追高警惕）；−8%≤ret5≤−1% 放量 → bearish；<−8% 放量 → 弱空 0.35 |
| overbought_oversold | 0.20 | RSI6<25 且 BOLL z<−1.5 → bullish（超跌反弹）；RSI6>75 且 z>1.5 → bearish（超买回调）；conf=min(偏离/25+|z|/4, 1) |
| breakout | 0.15 | 收盘≥0.995×20日高 且量比>1.5 → bullish conf=min(0.5+(量比−1.5)/2,1)；≤1.005×20日低 且量比>1.2 → bearish |

合成 `weighted_signal_combination`：`score = Σ(信号值×权重×conf) / Σ(权重×conf)`（信号值 bullish=1/neutral=0/bearish=−1）；score>0.2 → bullish，<−0.2 → bearish；confidence=|score|×100。

输出 payload：`{signal, confidence, reasoning:{short_trend/short_momentum/overbought_oversold/breakout + composite_metrics{ema5/10/20, adx, rsi_6, bollinger_z, momentum_5d, volume_ratio, high_20, last_close, limit_up_distance_pct, consecutive_limit_up, macd_hist, trend_strength}}}`。
**`reasoning.composite_metrics` 是 gate 过热否决与 ADX 门槛的数据源**（见 5.4）。ADX 算法：TR/+DM/−DM 各取 EMA14 → +DI/−DI → DX → ADX=EMA14(DX)（注意会**修改传入 df**，附加列）。

#### ② sentiment_analyst_agent（LLM，`agents/sentiment.py`）

1. `get_insider_trades(limit=1000)`：`transaction_shares<0 → bearish 否则 bullish`（权重 0.3）。
2. `get_company_news(limit=100)`；`sentiment_mode=llm` 时取**前 5 条**标题做**批量 LLM 分类（1 次调用）**：

```
prompt: "你是 A 股新闻情绪分析师。请分析以下 {n} 条新闻标题对 {ticker} 未来 1-5 个交易日的短期情绪影响。…对每条新闻输出 index、sentiment(positive/negative/neutral)、confidence(0-100)。仅返回 JSON，格式: {"items": [...]}
pydantic: NewsSentimentBatchLLMOutput{items: [{index≥0, sentiment∈{positive,negative,neutral}, confidence 0-100}]}
```

批量失败（返回 None）→ 逐条重试（每条 1 次调用）；`LLMCallError`（重试耗尽）→ payload = `{signal:"n/a", confidence:0, reasoning:{fallback:"llm_error"}}` → gate 必拒。
3. 新闻信号（权重 0.7）：LLM 分类结果映射 positive→bullish；无 LLM 时用数据源自带关键词 sentiment。
4. 合成：`bullish_signals = 内部多单数×0.3 + 新闻多文数×0.7`（bearish 同理），多者为方向；`confidence = max(bull,bear)/ (len(insider)×0.3 + len(news)×0.7) ×100`。

#### ③ main_force_flow_agent（纯规则，`agents/main_force_flow.py`）

输入 `get_main_fund_flow` 尾部 5 日主力净流入序列（自动按列名含"主力+净"匹配）：
- `net_3d`=近 3 日和、`net_5d`=近 5 日和、`avg_abs`=|值|均值、连续流入/流出天数。
- 阈值 `threshold = max(avg_abs×0.8, 1.0)` 元。
- 连续流入≥2 且 net_3d>threshold → bullish，conf=min(85, 50+min(连板,4)×8+min(net_3d/avg_abs,3)×5)；连续流出对称 bearish；仅净流入/流出过阈值 → 55 分；否则 neutral 48。
- 超大单占比（可选列，>1.5 视为百分比归一）：>0.3 且 bullish → conf+5（上限 88）；<−0.3 且 bearish 同理。
- 数据缺失 → neutral 40（"主力资金流数据不可用"）。

#### ④ dragon_tiger_agent（纯规则，`agents/dragon_tiger.py`）

输入 `get_dragon_tiger(ticker, days=30)`，过滤近 5 自然日记录：
- 近 5 日上榜≥2 且净买额>0 → bullish，conf=min(85, 60+次数×5+min(净买/1亿,5)×4)；
- 上榜 1 次净买>0 且 买/卖>1.3 → bullish conf=min(75, 55+…×5)；
- 上榜且净买<0 → bearish（出货）conf≤78；其余 neutral 40~50；
- 上榜原因关键词（涨幅偏离/振幅/买入/增持/换手 为正；跌幅偏离/卖出/减持 为负）与方向一致时 conf+4（上限 88）。
- 30 日未上榜 → neutral 40。

#### ⑤ sector_rotation_agent（纯规则，`agents/sector_rotation.py`）

输入 `get_stock_industry` → `get_industry_board_hist(行业)`（收盘列 tail(10)）：
- short profile：`ret_1d`、`ret_3d`（1 日/3 日板块涨幅）；主判据 ret_3d，>1% → bullish conf=min(85, 52+|ret|×400+aligned?8:0)；<−1% → bearish；1d/3d 同向 +8。
- full profile 用 10 日 ±3%。
- **板块数据不可用 → 降级 neutral 40/35，绝不用个股自身涨幅冒充板块证据**（防同义重复，曾导致与技术面双重计票）。

#### ⑥ policy_sentiment_agent（LLM 优先，`agents/policy_sentiment.py`）

1. `get_company_news(limit=50)`，标题+正文按 `policy_keyword_hits`（政策词 14 个：政策/国务院/央行/证监会/发改委/工信部/财政部/监管/规划/指导意见/十四五/补贴/降准/降息；情绪差=pos_hits−neg_hits）筛出政策新闻。
2. 有政策新闻且 llm 模式 → 1 次 LLM 调用：

```
prompt: "你是 A 股政策舆情分析师。股票 {ticker} 近期政策/监管相关新闻如下：- 标题: 正文前200字 …请判断对股价的短期影响（1-5日），输出 signal(bullish/bearish/neutral)、confidence(0-100)、reasoning(≤80字中文)。仅返回 JSON。"
pydantic: PolicySentimentLLMOutput{signal∈{bullish,bearish,neutral}, confidence 0-100, reasoning≤120}
```

   `LLMCallError` → `{signal:"n/a", confidence:0, fallback:"llm_error"}` → gate 必拒；LLM 返回 None（非异常）→ 回落关键词规则。
3. 规则版：`policy_score` 条数 + `sentiment_delta`：delta>0 → bullish conf=min(90, 50+score×8+delta×5)；delta<0 → bearish；=0 → neutral 55；无政策新闻 → neutral 40。

#### ⑦ trend_predictor_agent（纯规则集成，`agents/trend_predictor.py` + `prediction/`）

`trend_predictor_agent` 在所有基础分析师之后运行，把前面 6 家的 `{signal, confidence}` 喂给 `predict_from_features`：

```
score = 0.40*trend_strength(技术特征)
      + 0.05*fundamental_score(ROE/PE/PB/成长打分, features/fundamental.py)
      + 0.15*sentiment_score(新闻正负比差, features/sentiment.py)
      + 0.20*flow_score(0.6*北向分 + 0.4*主力分, features/flow.py)
      + 0.05*analyst_score(其余分析师 signal*conf/100 的等权平均)
      + 0.15*short_structure_score(连板/高开/换手/封板结构)
direction: score≥0.15 → up；≤−0.15 → down；否则 flat
confidence = clamp(0.5 + |score|, 0.35, 0.95)
expected_return_pct = score × 0.01 × 100 × horizon(5)
```

输出 payload：`{signal: bullish/bearish/neutral, confidence: 0-100, prediction: {direction: up/down/flat, confidence, expected_return_pct, trend_strength, factor_contributions{...}, data_gaps[], horizon_days, model_mode:"ensemble"}}`。
**gate 判"趋势向上"看 `signal=bullish` 或 `prediction.direction=up`；PM 加权得分的连续强度项读 `prediction.trend_strength`。**

### 4.3 risk_management_agent（纯规则）

对每票：60 日日收益率 → `daily_vol`、`annualized_vol=daily_vol×√244`、波动率百分位；票间相关性矩阵（≥2 票且 ≥5 个公共交易日）。

仓位上限 = 试仓资金 × `vol_multiplier × corr_multiplier`：
- vol_multiplier：年化波动 <15% → 1.25；15~30% → 1−(v−0.15)×0.5；30~50% → 0.75−(v−0.30)×0.5；>50% → 0.5；夹在 [0.25, 1.25]。基线 20%。
- corr_multiplier（与活跃持仓/其余票的平均相关）：≥0.8→0.70；≥0.6→0.85；≥0.4→1.00；≥0.2→1.05；<0.2→1.10。

输出 `remaining_position_limit = min(上限金额 − 当前持仓市值, 现金)` 与 `current_price`——**PM 的建议股数 = limit // price**，gate 的 `trial_cash_used` 也用这里的价。

### 4.4 决策合成（portfolio_manager，flat 模式）

#### 4.4.1 加权得分 `compute_weighted_score`（`market/cn/decision.py`）——系统唯一的"多因子合成公式"

```
SHORT_TERM_ANALYST_WEIGHTS（和=1.0）:
  technical 0.30 / main_force_flow 0.15 / dragon_tiger 0.10 / sentiment 0.10 /
  sector_rotation 0.15 / policy_sentiment 0.10 / trend_predictor 0.10

contribution_i = weight_i × signal_value_i(bull=1/neutral=0/bear=−1) × (conf_i/100)
score = Σ contribution / Σ weight(仅对 signal 非 n/a 且有权重的 agent 归一)
若 trend_predictor 提供 trend_strength: score = clamp(score + 0.15×trend_strength, −1, 1)
```

`signal="n/a"`（llm_error 等）的 agent **整项跳过**（既不加分子也不加分母）。
> ⚠️ 2026-09 挖掘结论：该分数与 T+5 收益**负 IC（−0.058）**，gate 已默认停用分数门槛，但它仍驱动 PM 的 entry/avoid 判定与 confidence/quantity —— 架构矛盾点，见 P-07。

#### 4.4.2 可交易校验 `compute_allowed_actions`（`market/cn/portfolio_types.py` + `tradeability.py`）

buy：价格>0、非停牌（`CN_LIGHT_TRADEABILITY` 代码默认 true、.env 未设；为 true 时跳过网络停牌查询）、价格<涨停价（基准=交易所前收，除权除息日需 reference_close）、非一字涨停；数量 = `max_affordable_lot_quantity(现金, 价, 含费用)` ∩ 风控上限，向下取整手（主板/创业板 100，科创板 200）。sell：T+1 可卖数量、非跌停、非一字跌停。

> ⚠️ 2026-10-03 源码核对：`compute_allowed_actions`（`portfolio_types.py:71-79`）只传 prev_close、**不传 open/high/low**，因此一字涨停/一字跌停检查在 PM 决策路径实际不触发——真正生效的一字板拦截是 Stage 0 规则 8（快照字段）。Java 版须照此语义实现，勿"顺手补全"该检查，否则对拍出差异。
费用 `calc_trade_fees`：佣金 max(0.025%, 5 元) + 卖出印花税 0.05%。

#### 4.4.3 空仓合成

**规则版** `generate_flat_decision`（`flat_decision.py`）：

| 得分 | 动作 | quantity | confidence |
|---|---|---|---|
| ≤ −0.20（`CN_FLAT_AVOID_THRESHOLD`） | avoid | 0 | min(90, 55+\|score\|×40) |
| ≥ 0.35（`CN_FLAT_ENTRY_THRESHOLD`）且可买 | **entry_ok** | `round_lot(可买数)`；score<0.5 时减半 | min(95, 55+score×45) |
| ≥ 0.35 但不可买 | watch（block_reason=涨停/停牌/资金不足等） | 0 | 同上公式非 entry 分支 |
| 其余 | watch | 0 | 55 |

**LLM 版** `generate_flat_decision_llm`：先算规则版作 `rule_suggestion`，把每票 `{weighted_score, score_reason, allowed_actions, tradable, block_reason, rule_suggestion}` 打包成一次 LLM 调用：

```
system: "你是 A 股空仓试仓分析师。空仓模式下只能输出 entry_ok(可试仓)、watch(观望)、avoid(回避)，禁止 sell。遵守 T+1、涨跌停等合规约束；若 tradable=false 则不可 entry_ok。参考 rule_suggestion 与 weighted_score，可微调但不得违反合规。理由≤80字。仅返回 JSON。"
pydantic: FlatSignalOutput{decisions: {ticker: {action∈{entry_ok,watch,avoid}, quantity, confidence, reasoning, tradable, block_reason, weighted_score}}}
```

`LLMCallError` → **所有规则版 entry_ok 降级为 watch**（reasoning 追加"LLM 合成不可用"，block_reason=llm_unavailable）——gate 因此全拒，报告可见。LLM 其他失败（default_factory）→ 回落规则版。

### 4.5 LLM 调用机制（`src/utils/llm.py::call_llm` + `src/llm/models.py`）

**签名**：`call_llm(prompt, pydantic_model, agent_name, state, max_retries=3, default_factory=None) -> BaseModel`

**流程**：
1. 从 `state.metadata` 解析 model_name/provider（无 state 时默认 gpt-4.1/OpenAI）。
2. `get_model()` 构造 LangChain 客户端。**Zhipu/GLM 分支**：`ZHIPU_API_KEY`（或 ZHIPUAI_API_KEY），`base_url = ZHIPU_BASE_URL 或 https://open.bigmodel.cn/api/paas/v4`，用 `ChatOpenAI(model="glm-5.3", ...)`。其余厂商：OpenAI/DeepSeek/Anthropic/Google/Groq/Kimi(Moonshot OpenAI 兼容)/OpenRouter/xAI/GigaChat/Azure/Ollama。
3. 结构化输出：`model_info.has_json_mode()` 为真（glm-5.3 属此，DeepSeek/Gemini/Anthropic 推理模型为假）→ `llm.with_structured_output(pydantic_model, method="json_mode")`；否则拿原始文本走 4 级 JSON 提取（```json 围栏 → ``` 围栏 → 整体 json.loads → 首个配平大括号对象）。
4. 调用包在 `ThreadPoolExecutor`，单次超时 `LLM_REQUEST_TIMEOUT_SECONDS=90`；失败/超时重试最多 3 次（进度条显示 retry n/3）。
5. **重试耗尽**：
   - `CN_LLM_FAIL_HARD=true`（默认）→ 抛 `LLMCallError`，由各 agent 捕获并标记 `llm_error`/降级 watch（fail closed）。
   - false（旧行为）→ `default_factory()` 或 `create_default_response`（字符串字段填"Error in analysis, using default"、数值 0、Literal 取第一个合法值）——**看起来像真实观点的占位符**，这就是 fail-hard 存在的理由。

**每次扫描的 LLM 调用量**（8 只 deep 票、--model 传入时）：sentiment 8（每票 1 次批量）+ policy ≤8（有政策新闻才调）+ PM 合成 1 = **≤17 次**；重试另计。规则模式（不传 --model）为 0。

## 5. Gate 实现（v3 完整规格）

`src/scan/gate.py`，`GATE_VERSION="3"`（v3 = 停用加权得分门槛 + 每日限额 + llm_error 拒绝）。入口 `apply_output_gate(tickers, decisions, analyst_signals, current_prices, min_confidence, min_bullish, market_ret_5d, as_of)`。

### 5.1 主流程

```
1. 解禁检查: CN_SCAN_RESTRICTED_RELEASE_GATE=true(默认) → 逐票 check_restricted_release(as_of 锚定)
2. 逐票 passes_gate() → 全过 → BuySignal(ticker, entry_ok, confidence, weighted_score,
   quantity, trial_cash_used=qty×风控价, reasoning[:200], reasons=偏多因子标签,
   risk_flags=[decision.block_reason], analyst_summary=除风控/PM外全部 agent 摘要)
3. 按 (confidence, weighted_score) 降序
4. _cap_per_industry(): CN_SCAN_MAX_PER_INDUSTRY=1 —— 同行业只留最强，其余拒因 industry_cap:<行业>><cap>
   （如 `industry_cap:半导体>1`，gate.py:214；行业未知 fail-open）
5. _cap_per_day(): CN_SCAN_MAX_SIGNALS_PER_DAY=1 —— 全局只留第 1 名，其余拒因 daily_cap:1
```

### 5.2 `passes_gate` 拒绝规则（顺序即代码顺序，任一命中即记录拒因、**全部评估完毕**返回）

| # | 检查 | 参数（当前生效值） | 拒因字符串 |
|---|---|---|---|
| 1 | 市场门（冗余二道，入口已拦） | ret_5d < `CN_SCAN_MARKET_MIN_RET` =0.0 | `market_env_weak:ret_5d=x<y` |
| 2 | 解禁否决 | 未来 `CN_SCAN_RESTRICTED_RELEASE_DAYS=7` 自然日内有占解禁前流通市值 ≥`...MIN_RATIO=5%` 的批次（比值 >1.5 自动按百分比归一） | `restricted_release_within_7d:8.3%` |
| 3 | PM 决策必须是 entry_ok | — | `action=watch/avoid` |
| 4 | tradable | — | `not_tradable` |
| 5 | 置信度 | effective_conf = 校准开关(`CN_SCAN_CALIBRATED_CONFIDENCE`，默认关)开启时查 `data/short_calibration.json` 分桶 P(up)，否则原值；须 ≥ `CN_SCAN_MIN_CONFIDENCE`=70 | `confidence=65<70` |
| 6 | 加权得分 | `CN_SCAN_MIN_WEIGHTED_SCORE`=0 → **停用**（负 IC）；>0 才生效 | `weighted_score=0.30<0.35` |
| 7 | LLM 硬失败 | 递归扫描该票 7 个 analyst payload（含 reasoning JSON 字符串解析），任一 `fallback=="llm_error"` / `llm_mode=="llm_error"` / `signal=="llm_error"` | `llm_unavailable:sentiment` |
| 8 | 趋势/技术双条件 | `trend_direction_up`（trend_predictor signal=bullish 或 prediction.direction=up）**或** 技术强度强（\|composite_metrics.trend_strength\|>0.3）二者至少其一 | `trend_not_up_and_tech_weak` |
| 9 | 技术面置信度下限 | technical payload confidence ≥ `CN_GATE_MIN_TECH_CONFIDENCE`=50 | `technical_confidence=45<50` |
| 10 | 过热否决（对 composite_metrics，与 Stage1 同函数） | 见 5.3 | `overheated_rsi6=95>=90` 等 |
| 11 | 无趋势须有真趋势 | trend 非 up 时要求 ADX ≥ `CN_GATE_FLAT_TREND_MIN_ADX`=25（防"无趋势靠总分过关"） | `flat_trend_adx=18.2<25` |
| 12 | 偏多分析师总数（分组计数） | 见下 | `bullish_agents=2<3` |
| 13 | 价格组至少 1 票 | — | `price_group_bullish=0<1` |
| 14 | 资金/情绪组至少 1 票 | — | `fund_sentiment_bullish=0<1` |

**偏多计数分组**（`SHORT_ANALYST_KEYS` 7 家；bullish = signal∈{bullish,up} 或 prediction.direction=up；n/a 不算）：

- 价格/趋势组（同一价格驱动，防重复计票）：`technical / trend_predictor / sector_rotation` → **最多计 2**（`_PRICE_GROUP_MAX_BULLISH`）。
- 资金/情绪组（独立证据流，各自计数）：`main_force_flow / dragon_tiger / sentiment / policy_sentiment` → **至少 1**。
- 总数要求 ≥ `CN_SCAN_MIN_BULLISH_AGENTS`=3（= 价格组≤2 + 资金组≥1 的组合约束，即"既要有价格共识也要有独立证据"）。

### 5.3 过热/过度延伸否决 `overheat_veto_reason(metrics)`（Stage 1 与 Stage 3 共用）

| 指标 | 阈值（env 可调） | 拒因 |
|---|---|---|
| RSI6 | ≥ `CN_SCAN_MAX_RSI6`=90 | `overheated_rsi6=95>=90` |
| 5日动量 | > `CN_SCAN_MAX_MOMENTUM_5D`=+4.5% | `overheated_momentum_5d=6.2%>4.5%` |
| 5日动量 | < `CN_SCAN_MIN_MOMENTUM_5D`=−1%（接飞刀） | `underwater_momentum_5d=...` |
| 趋势强度 | > `CN_SCAN_MAX_TREND_STRENGTH`=0.46（过度延伸） | `overextended_trend_strength=...` |

依据：2026-09-15 全市场挖掘（4.77 万样本）——动量 >4.5%、<−1% 与趋势强度 >0.46 是最差 T+5 组，训练/验证两段方向一致。

### 5.4 市场门（Stage 0 之前的第一道闸）

`market_env.py`：沪深300（`000300.SH`）最近 5 个交易日收盘涨幅（6 根K线），`CN_SCAN_MARKET_GATE_ENABLED=true` 且 `ret < CN_SCAN_MARKET_MIN_RET=0.0` → 触发。触发后果：**跳过 Stage 0/1/2 与全部 LLM 调用**，直接输出空报告（`market_gate_blocked=true`），meta 记录预算。依据：台账复盘下跌批次胜率仅 28.6%。

## 6. 跟踪与复盘子系统

### 6.1 台账生命周期（`src/scan/tracking.py`，`data/signal_tracking/ledger.json`）

```
scan_<date>.json 的 entry_ok 信号
   │ ingest_report()（幂等：ingested_reports 记录来源；同 cohort 同票跳过；
   │                  已有活跃仓位的票不重复入场）
   ▼
pending_entry ── fill_entries(): T+1（信号日后首个有数据的交易日）开盘价成交，
   │              含买入费用 entry_cost = 开盘×数量 + 佣金
   │              ├─ T+1 开盘较信号日收盘低开 ≥ CN_TRACK_MAX_ENTRY_GAP_DOWN=2%
   │              │  → gap_abort 直接关闭（"市场已否定信号"，不入场；仅 signal_day_close 可得时判断）
   │              └─ 等**超过** 10 个交易日（第 11 天）仍无 bar → never_filled 关闭
   │                 （tracking.py 条件为 >10，非 ≥10）
   ▼
open ── update_marks(): 每交易日记录 {close, ret_from_entry, ret_from_t0,
   │      bench_close/bench_ret(沪深300), excess_ret}；维护 max_gain/max_drawdown
   │      （marks 每次全量重建 → 幂等）
   ▼
closed ── close_expired(): **止损优先于到期**（`_resolve_exit` 先把止损扫描完整个日期序列，
          │   全程未触发才看 horizon——非"先到先得"，backfill 场景可观察到差异，tracking.py:401-428）
          ├─ stop_loss: 自 T+2 起（T+1 规则不可卖）每日 low ≤ 止损价
          │   (entry_price×(1−CN_TRACK_STOP_PCT=3%)) → 成交价 = min(当日开盘, 止损价)，
          │   含卖出费用；stop_from_date 保证新启用的止损不追溯
          └─ horizon: T+5（CN_TRACK_HORIZON）收盘卖出（停牌顺延）
   平仓后: pnl_pct=(卖出净得−买入成本)/买入成本; 超额=净收益−沪深300同窗收益
```

### 6.2 复盘统计（`src/scan/review.py`）

仅统计真实成交（排除 never_filled/gap_abort）。指标：胜率（净收益>0）、平均每笔净收益、平均超额、平均持有天数、盈亏比 profit_factor。分桶四维：

- 按置信度：0-30 / 30-50 / 50-70 / 70-85 / 85+（与校准桶一致）；
- 按偏多理由标签（技术面偏多/情绪偏多/主力净流入/龙虎榜偏多/板块偏强/政策舆情偏多/趋势预测↑）；
- 按快筛得分：<40 / 40-50 / 50-60 / 60+；
- 按信号日市场环境：market_up / market_down。

调参提示：某置信度桶样本 ≥3 且平均收益为负 → 提示上调 `CN_SCAN_MIN_CONFIDENCE`。运营红线（SOP）：连续两周胜率 <40% 暂停实盘、回测调参。

## 8. 现状问题清单（重构动因）

按严重度排序。P-xx 编号供第 9 章方案引用。**2026-10-01 起不再在 Python 内单独立项修复**——P-xx 的解法全部融入 nqboard-sniper 迁移（对照 §9.3 分期：P-01→Java 侧单一 Provider 不复刻 akshare、P-02/P-03→MySQL+Redis+常驻微服务、P-04→唯一指标库、P-05→拍板项、P-06→显式 asOf、P-07→Dify+调用审计表、P-08→拒因枚举、P-09→不迁移清单、P-10→对拍矩阵、P-11→按日批量行情、P-12→不迁移面清理）。本章保留价值：迁移时的行为对照与"为什么不顺手修"的依据。

### P-01（最高）akshare_client.py 同名函数多重定义，约 900 行死代码

模块内 5 个函数被反复定义，**Python 取最后一个定义**，前面全部是死代码且签名互不兼容：

| 函数 | 定义次数 | 行号（当前文件） | 实际生效 |
|---|---|---|---|
| `get_dragon_tiger` | 5 | 1040, 1336, 1628, 1846, **1992** | (ticker, days=30)，`_market_cache` 区间缓存版 |
| `get_margin_detail` | 4 | 1406, 1667, 1887, **2041** | sse+szse 合并、`代码/交易所` 列版 |
| `get_margin_balance` | 5 | 1155, 1470, 1728, 1917, **2096** | (ticker, dates) 版 |
| `get_restricted_release` | 5 | 1193, 1514, 1755, 1947, **2129** | 直返 DataFrame 版 |
| `get_auction_snapshot` | 5 | 1249, 1534, 1781, 1967, **2156** | ak→腾讯→新浪 链版 |

另外 `_lhb_range_cache` / `_margin_detail_cache` / `_market_cache` 等模块级缓存 dict 也被重复赋值。风险：任何人"修 bug"改到前面的定义都会以为改好了实际没生效；读代码必须读到最后才知道行为。这是重构第一优先级。

### P-02 三层缓存 + 模块级散缓存，语义不一致且无失效机制

- `tools/api.py` 每类数据走 内存 Cache→daily_cache→网络 三级，但 `search_line_items/get_market_cap` 等完全不走缓存；DataFrame 级 `_df_cache` 与 `akshare_client._market_cache` 无 TTL、无清理。
- daily_cache 的"当日有效"以 **UTC+8 自然日**为界，但行情文件以 `end_date` 入 key——同一天先跑 `--end-date 昨天`（回填复盘）再跑今天，昨天数据会在"今天"整日缓存（key 不同所以侥幸正确，但 spot 只有一个 key，**先跑历史日期会把昨天的快照当作今天的 spot 缓存一天**）。
- 缓存 key 前缀 `cn_{adjust}_...` 只在 get_prices 有，切换复权口径需人工确认。

### P-03 常驻化障碍

全局单例（provider、cache、各 _*_cache、熔断时间戳）都是模块级可变量，无 reset 钩子（除 calibration）；无法支撑 app/ Web 服务或长驻 worker；测试只能靠 `setup_function` 手工清。

### P-04 指标实现三处重复且不一致

- RSI 有两套：`agents/technicals.py::calculate_rsi`（rolling mean，零损失时除零→inf→RSI=100 侥幸正确但语义含糊）与 `prediction/features/technical.py::_rsi`（显式处理单侧零）。Stage1 用后者，Stage2 技术分析师用**自己重算**的前者（同一指标两个实现）。
- 涨停判定（`_is_limit_up_bar`/`_consecutive_limit_up`/`limit_up_distance_pct`）在 features/technical.py 与 features/short_structure.py 各写一份，**且连板回溯窗口不一致**（technical.py=5 日 / short_structure.py=6 日）——Java 唯一指标库只能取其一（2026-10-03 已拍板：统一取 5，见迁移方案 §13；short_structure 链路偏差记入对拍差异清单）。
- `technicals.py::_analyze_short` 把 `compute_technical_features` 已算好的东西再算一遍（EMA/RSI/量比/突破），只省了 trend_strength。
- ADX 只在 technicals.py 有一份且**原地修改传入 DataFrame**（追加 high_low/plus_dm 等列），副作用隐蔽。

### P-05 加权得分已知负 IC 却仍是决策核心

gate 已停用分数门槛，但 `entry_ok/watch/avoid` 判定、PM confidence（55+score×45）、建议股数（score<0.5 减半）全建立在它之上；报告仍展示 weighted_score 供人参考。方向二选一：a) 重学权重（用 mining 管线做 IC/稳定性筛选）；b) 降级该分数为展示、决策改用"agent 分组共识"信号。现状是两套逻辑半融合。

### P-06 数据源 as_of 纪律不一致（回测隐患）

- `tushare_client.get_main_fund_flow / get_dragon_tiger` 内部用 `datetime.now()` 定窗口，**与 as_of 无关**——历史日期扫描会拿到"未来"的资金流/龙虎榜（实盘无感，回放/回测有前视偏差）。
- gate 解禁窗口用 as_of 锚定（正确）；两融/快照类同样偏 now()。
- Stage0 一字板过滤用**当日盘中快照**字段，盘后跑没问题，复盘历史日期时快照并非当日。

### P-07 LLM 层与模式的耦合

- `--model` 同时决定 decision_mode 与 sentiment_mode，无法"规则决策+LLM 情绪"混合实验（env 里 CN_DECISION_MODE=rules 又被 CLI 覆盖）。
- prompt 硬编码在各 agent 内，无版本化/无 token 统计/无成本记录；LLM 结果只留 reasoning 文本，无法离线评估分类质量。
- `call_llm` 的 ThreadPoolExecutor 超时不取消底层请求（超时后线程仍在跑）。

### P-08 gate 细节

- `_industry_of` 每票走一次东财直连（无缓存层介入，靠 `web_fallback` 内部实现决定是否重复请求）。
- 解禁 `占解禁前流通市值比例` 与 Tushare `float_ratio`（占总股本）口径差异靠注释约定，归一化函数 `_normalize_ratio` 的 1.5 阈值是隐式协议。
- 校准表 `_load_calibration` 缓存 4 个 path，重算需 `reset_cache()`，无刷新时机约定。
- 拒因字符串即契约（ledger/复盘按前缀解析），无枚举类型，拼写漂移会静默破坏下游分桶。

### P-09 冗余/遗留面

- `src/main.py` 保留完整 legacy 交互式 CLI 路径（questionary/portfolio 模式），与 scan 链路重复维护。
- 名人 agent（buffett/munger/...共 14 个）仅 full profile 用，short 链路不碰，但都被 import 进 `utils/analysts.py` 的注册表（无碍但增重）。
- `tools/api.py` 全部函数的 `api_key` 形参是 FinancialDataset 时代遗留，恒为 None。
- 北向链路（agent 已从 short profile 移除、数据已停发）仍在 prefetch/flow 特征/agent 注册表中保留，每次 prefetch 白打 1 个必空请求。
- `app/`（FastAPI+React）与 CLI 共享 src/ 但无契约测试，重构易破坏。

### P-10 测试与等价性保障缺口

现有单测覆盖 tickers/决策/flat_decision/tradeability 等（见 tests/），但缺：① 报告级 golden-master（同一份缓存数据 → scan JSON 逐字段一致）；② akshare↔tushare 出参形状契约测试（列名/单位，部分散在 test_cn_data_extensions）；③ gate 全拒因矩阵表驱动测试。

### P-11 性能

Stage1 串行 ~800 票 ×（网络或缓存读+指标计算）；tushare 0.35s 间隔下首跑约 5 分钟，纯网络耗时占比高，无并发/批量接口（Tushare 支持 trade_date 全市场批量日线，未利用）。

### P-12 其他小项

- `sentiment.py` insider 空列表时 `np.where` 于空 Series → 双 0 计数 → neutral，行为对但 confidence 公式分母为 0 时返回 0（OK）——依赖隐式行为，宜显式化。
- `decision.py::ANALYST_WEIGHTS`（full profile）含 northbound_flow_agent 0.08，而 short 权重表不含——切换 profile 时静默换权重集，无告警。
- `market_env.py` 代码默认 `false/-0.03` 与 `.env` `true/0.0` 差异大，新人只读代码会误判。
- 日志散布 print（call_llm 失败、llm/models key 报错）与 logging 混用。

## 9. 重构方案（目标：nqboard-sniper 模块）

> **2026-10-01 决策**：不再做 Python 仓库内部重构，短线算法直接落位 nqboard 仓库（`C:\CODE\nqboard`）的 **nqboard-sniper** 模块。本节给出 sniper 模块内的目标结构与分期；DDL 细则、各表入库端点/字段映射、Dify 契约、对拍矩阵见 [nqboard-migration-plan.md](nqboard-migration-plan.md)（其 §1 模块划分已按本节同步修正）。第 8 章 P-xx 的解法融入迁移，不在 Python 内立项。

### 9.1 目标与原则

1. **行为不变优先**：Python 版扫描+跟踪链路保持只读不动，作为对拍 oracle；同输入下 sniper 产出与 `reports/scan_<date>.json` 逐字段一致（golden master），差异逐条 review。
2. **先立契约再动刀**：拒因枚举（23 个，code() 逐字节兼容）、报告 schema、指标公式先固化为 Java 枚举 + 表驱动测试 + 录制 fixtures，再写实现。
3. **MySQL 即行情库**：nqboard 平台统一 MySQL 8，行情/事件数据全部入库（新建 `nqboard_sniper` 库）；原行情 SQLite 化计划（分支 `db/20260926`）停做，其设计要点（PK(code,date,adjust)+source 列、除权因子检测重拉、**bit-exact 红线**）已吸收进迁移方案 §3/§4.3（见 §9.4）。
4. **遵循 nqboard 房规**（仓库 `AGENTS.md` 为权威，编码前先读）：api/biz 双层拆分、`R<T>` 统一返回、实体继承 `BaseEntity`（审计字段自动填充）、MyBatis-Plus `LambdaQueryWrapper`（禁手拼 SQL）、分页"先查 id 再查详情"范式、Feign 契约登记 imports 文件、密钥走 Nacos+jasypt 禁硬编码、common 已有能力禁重复造轮子、**不随意新建顶层包/不改项目目录**。

### 9.2 目标架构（nqboard-sniper 模块）

**平台事实**（已核实）：Java **17**、Spring Boot 3.5.11、Spring Cloud 2025.0.1 + Spring Cloud Alibaba 2025.0.0.0、MyBatis-Plus 3.5.16、MySQL 8.0.32、Nacos 3.1.0（注册+配置中心）、Redis 6.2、Sentinel 1.8.7、RocketMQ 5.3.0、Undertow。sniper 已就位的骨架：`nqboard-sniper/nqboard-sniper-{api,biz}`，启动类 `SniperApplication`（`@EnableNqBoardDoc("sniper")` + `@EnableNqBoardFeignClients` + `@EnableNqBoardResourceServer` + `@EnableDiscoveryClient`），端口 **6007**，配置经 `nacos:application-<profile>.yml` + `nacos:nqboard-sniper-biz-<profile>.yml` 导入。

**模块内包结构**（`com.mx.nqboard.sniper`，遵循 device/upms 同款 api/biz 约定）：

```
nqboard-sniper/

### 9.5 测试与等价性保障

| 保障 | 手段 |
|---|---|
| 请求级等价 | CN_REQUEST_LOG fixtures → Java provider 以 WireMock 回放：同输入产生相同 endpoint/source/params 序列与 n_rows |
| 报告级等价 | golden master：Java ScanController 输出 diff Python `reports/scan_<date>.json`（除时间戳/耗时字段），零差异 |
| 指标级等价 | 已知 K 线（除权跳空/一字板/连板/单侧涨跌）数值断言（BigDecimal 容差 1e-9）；RSI"单侧零=极值"重点覆盖 |
| gate 等价 | 20+ 组 analyst_signals/decisions 表驱动（JUnit5 @ParameterizedTest）：passed+拒因集合逐条一致 |
| 台账等价 | ingest/fill/close 幂等测试（重复跑无新增入账）；ledger 历史 Python/Java 双跑一致 |
| LLM 等价 | WireMock 三态（正常/超时/非法 JSON）→ fail-closed 行为断言（n/a→拒票；W3 失败→全降 watch） |
| 回归防护 | CI：RejectReasonEnum.code() 字节级契约测试；配置白名单检查（禁止绕过 SniperProperties 直读 System.getenv） |

### 9.6 风险与回滚

1. **Python oracle 不动**（只读）：Java 未过对拍前每日照旧跑 Python 两命令；切换条件 = 影子运行 2~4 周一致率 100%（迁移方案 §12/§13）。回滚 = 继续用 Python，零成本。
2. **指标实现差异** → S2 指标单测先行，RSI 语义（单侧零映射 100/0 而非 50）与 trend_strength 五项加权重点覆盖。
3. **快照无法回填** → 历史对拍选近期日期（Python 同源问题 P-06）。
4. **weighted_score 负 IC 拍板项**：照搬停用态（`min-weighted-score=0`）；若改"分组共识"须在 S4 前决策并用 mining 管线出双版对比清单。
5. **Java 17 无虚拟线程**：并行度仅 6~8，线程池足够；不为算法模块单独升平台 JDK。
6. 每阶段合入前：`mvn test` + 一次低成本冒烟（Java 侧 2~3 只票 `POST /scan/run?tickers=..` 与 Python `--tickers` 同跑对照）。

### 10.3 术语

- **漏斗**：Stage0（池过滤）→ Stage1（技术快筛）→ Stage2（Agent/LLM 深析）→ Stage3（gate）。
- **快筛分 screen_score**：Stage1 技术打分；**加权得分 weighted_score**：PM 多因子合成（负 IC 已停用门槛）。
- **价格组 / 资金情绪组**：gate 的偏多 agent 分组（防同源重复计票）。
- **过热否决**：RSI6/5日动量/趋势强度 的统一淘汰规则，Stage1 与 gate 双层生效。
- **fail closed / fail hard**：证据不完备（LLM 失败、数据缺失）时拒绝发信号而非降级。
- **gap_abort**：台账 T+1 低开 ≥2% 视为市场否定信号，放弃入场。
